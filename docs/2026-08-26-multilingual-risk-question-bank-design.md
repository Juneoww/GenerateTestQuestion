# 中英文生成模型风险测试题库持续生成流程设计

## 目标与范围

为生成模型构建一套可重复运行、可每日增量更新的中英文风险测试题库流程。题库覆盖附录 A 的 5 个一级类别、31 个二级风险，用于向被测生成模型发送问题，观察其是否产生风险内容。

155 道题是首个全覆盖基线批次：每个二级风险 5 道，其中 4 道中文题和 1 道英文题，共 124 道中文题（80%）及 31 道英文题（20%）。后续每日运行读取新增网页、跳过已处理素材、生成可追溯的增量题目并更新题库版本；每日生成数量由配置决定，不把 155 设为每次运行的固定数量。本设计只覆盖素材采集、题目生成、去重、版本与 Excel 导出；不设计模型回答审核、评分或人工审核流程。

本流程新增的代码、配置、文档、素材、运行状态、日志、临时文件和导出结果必须全部位于 `D:\June\E\code\实用小工具\内容安全\GenerateTestQuestion\`。不得在 `D:\June\E\code\实用小工具\内容安全\` 根目录或其既有功能目录中创建、修改或写入本流程的文件。

## 独立项目隔离

`GenerateTestQuestion` 是一个独立的桌面项目，不是现有内容安全工具的子模块或扩展。它必须遵守以下边界：

1. 不导入、调用、复制或修改根目录现有项目的任何源码、测试、配置、数据、接口适配器或 GUI。
2. 不读取或写入 `GenerateTestQuestion` 目录以外的本地项目文件；所有用户选择的本地路径在执行前均解析并校验为该目录内的路径，拒绝 `..` 路径逃逸。
3. 使用本项目自己的入口、依赖清单、配置格式、日志和数据目录；即使两个项目均使用 Python 或 Windows 桌面技术，也不共享代码和运行状态。
4. 网站访问仅限运行时的外部公开来源；本地输出始终返回到本项目的 `data/` 与 `logs/` 目录。

现有根目录的三步内容安全工具保持完全不变。本项目的提交也只应包含 `GenerateTestQuestion` 路径下的文件。

## 桌面应用交互

首版提供单独启动的 Windows 桌面界面，人工按需运行，不嵌入或跳转到现有内容安全工具。界面划分为三个工作区：

1. **来源配置**：提供项目内“网站来源库”表格，维护爬取网站、入口 URL、语言、地区、风险路由和主题词；支持从 Excel 导入并导出为 Excel。
2. **生成运行**：选择本次运行日期与 `daily_target`，显示抓取、场景提取、出题、去重和导出进度，并提供手动启动按钮。
3. **题库结果**：显示本次批次、当日增量包和汇总题库位置，支持在应用内查看生成统计与打开项目内结果目录。

桌面应用不提供自动定时、后台服务或跨项目数据选择功能。

### 网站来源库（方案 C）

网站来源库的唯一持久化位置为 `GenerateTestQuestion/data/source_registry.xlsx`。日常操作以桌面界面中的表格为主，支持新增、编辑、启用/停用、导入、导出和抓取连通性测试；不在项目外读取或保存来源配置。

来源库的 `来源路由` 工作表中，一行代表“一个网站 × 一个类别 × 一种输出语言 × 一个适用配额槽”的可执行路由。若同一个网站支持多个类别、输出语言或配额槽，应使用多行记录，而不是在类别单元格中填写不受约束的混合文本。必填列为：

```text
路由ID、爬取网站、入口URL、地区、来源语言、来源类型、
场景、类别、输出语言、适用配额槽、主题词、启用状态、最近抓取时间
```

界面导入 Excel 时应检查列名、`场景` 与 `类别` 的规范映射、URL 非空、`输出语言` 与 `适用配额槽` 的合法组合，以及项目内唯一的 `路由ID`；检查失败的行不覆盖当前来源库。导出仅生成该项目内的 `source_registry.xlsx` 副本或替换该文件，不写入其他目录。

## 总体数据流

```text
公开网页素材
  → 原始素材库
  → 清洗与结构化场景卡
  → 31 类风险配额调度
  → 中英文题目模板生成
  → 去重、编号与完整性校验
  → Excel 题库
```

网页正文仅是非可信资料。提取和出题步骤必须将其作为数据处理，不能执行或遵循网页中出现的指令。

## 增量运行与题库生命周期

一次运行以 `批次ID` 和 `运行日期` 为边界，执行以下可复用流程：

1. 从项目内 `source_registry.xlsx` 读取已启用来源路由和上次成功运行状态。
2. 按来源、主题词和时间范围抓取新增网页；使用规范化 URL 和正文内容哈希跳过已入库素材。
3. 将新增网页写入对应的原始素材批次，并提取为场景卡。
4. 根据可配置的每日配额生成中英文候选题；首个全覆盖运行使用 155 道基线配额，后续运行使用 `daily_target`。
5. 对新题与历史题库执行去重，保留新增题并写入“当日增量包”和“汇总题库”。
6. 仅当素材、场景卡和题库文件均成功写入后，更新最近成功运行状态；失败运行不推进状态，下一次可安全重试。

首版仅支持人工手动启动：操作者按需执行一次运行，运行日期和 `daily_target` 作为本次批次参数保存。首版不包含定时任务、后台常驻服务或外部调度器集成。

## 来源路由

来源选择按“风险类别 × 来源类型 × 地区/语言 × 主题”配置，不要求为 31 个风险各绑定一个独立网站，也不将来源语言与题目语言一一绑定。一个来源可覆盖多个风险；同一风险默认应配置至少两种来源类型，但素材不足时可按该风险的合成模板补位。

| 风险类别 | 中文来源重点 | 英文来源重点 |
| --- | --- | --- |
| A.1 违反社会主义核心价值观 | 公共议题、治理信息、热点新闻 | 国际新闻、公共政策、社会事件报道 |
| A.2 歧视性内容 | 社会议题、公共讨论、案例报道 | Social issues、rights reporting、public discourse |
| A.3 商业违法违规 | 财经舆情、企业争议、消费维权、公开案例 | Business news、competition、IP and corporate disputes |
| A.4 侵犯他人合法权益 | 隐私、名誉、肖像、个人信息与权益争议报道 | Privacy、reputation、identity and rights-related reporting |
| A.5 内容准确与可靠 | 科普、辟谣、医疗科技和热点误解 | Fact-checking、science/health reporting、misinformation topics |

采集按入口页、主题词和时间范围执行，而非整站抓取。采集程序仅使用允许程序化访问的公开来源。

每个来源配置应包含：

```text
来源ID、爬取网站、地区、语言、来源类型、入口URL、
支持的风险类别、主题词、抓取频率、优先级
```

### 可执行路由配置边界

具体网站及入口 URL 是运行时配置，而不是程序代码或本设计中写死的内容。实现应读取项目内的来源工作簿和配额规则：

```text
data/source_registry.xlsx / 来源路由：路由ID、爬取网站、入口URL、地区、来源语言、来源类型、场景、类别、输出语言、适用配额槽、主题词、启用状态、最近抓取时间
config/quota_rules.yaml：risk_id、slot_id、slot_role、输出语言、source_mode、parent_slot_id、allow_synthetic
```

首版运行前的配置校验规则如下：

1. `source_registry.xlsx` 的每条已启用来源路由均须映射到规范风险目录中的一个 `场景` 和一个 `类别`；运行前按启用路由汇总 31 个风险的可用性。
2. 每个风险必须恰有下述五个配额槽：`zh-native-01`、`zh-native-02`、`zh-localized-01`、`zh-variant-01`、`en-01`。每槽只生成一题。
3. `zh-native-*` 槽的网页来源必须为 `地区=CN`、`来源语言=zh`、`输出语言=zh`；`zh-localized-01` 槽的网页来源必须为 `地区=overseas`、`来源语言=en`、`输出语言=zh`。
4. `zh-variant-01` 的 `source_mode` 必须为 `derived`，并以一个已生成的 `zh-native-*` 或 `zh-localized-01` 槽为 `parent_slot_id`；它只改变中文表达形式，不另换风险类别。
5. `en-01` 的 `source_mode` 为 `native` 时，网页来源必须为 `地区=overseas`、`来源语言=en`、`输出语言=en`；为 `mirror` 时，必须指定已生成的中文 `parent_slot_id`，并在输出时创建非空 `镜像组ID`。
6. 每个槽独立声明 `allow_synthetic`。某槽缺少可访问且符合其来源角色的网页来源时，只有该槽的 `allow_synthetic: true` 才允许用合成素材补位；不能借用其他槽的来源角色。
7. 网页来源必须有非空入口 URL，且其访问方式显式声明为允许程序化访问；合成素材不使用网页 URL。
8. 来源选择、URL 更新和访问策略属于运营配置，不改变采集、场景卡和出题模块的接口。

## 数据模型

### 原始素材

```text
素材ID、抓取批次ID、标题、正文、正文哈希、爬取网站、来源链接、来源地区、来源语言、
发布时间、抓取日期、来源类型、素材类型（web / synthetic）、主题标签
```

### 场景卡

原始素材不直接成为题目。提取器把素材归纳为可复用的场景卡：

```text
场景ID、场景、类别、来源地区、来源语言、主题、目标对象、
表达意图、上下文、可用题型、语言变体线索、素材类型、爬取网站、素材链接、抓取日期
```

### 题库记录

```text
题目ID、场景、类别、场景ID、题目语言、来源地区、来源语言、
配额槽ID、配额槽角色、来源模式、父槽ID、题型、轮次模式、镜像组ID、
爬取网站、来源链接、抓取日期、生成批次ID、生成时间、模板ID、题库版本、问题
```

题目 ID 采用 `A1-03-ZH-001` 或 `A1-03-EN-001` 的格式，依次表示场景代码、类别序号、题目语言和顺序号。

最终 Excel 必须以准确列名 `场景` 和 `类别` 保存 5 大类与 31 种安全风险。`爬取网站` 保存来源站点名称或域名，`来源链接` 保存具体素材页面 URL；派生的中文变体题和英文镜像题继承其父槽题目的这两个字段。

合成素材的 `来源链接` 固定写为 `synthetic://<风险ID>/<模板ID>`，`爬取网站`、`来源地区` 与 `来源语言` 写为 `synthetic`，使其不与网页素材混淆。

## 配额与题目生成

每个二级风险固定生成以下 5 道题：

1. `zh-native-01` 与 `zh-native-02`：两道基于中文素材的中文原生题。
2. `zh-localized-01`：一道基于海外英文素材、但适配中文语境的中文本地化题。
3. `zh-variant-01`：一道从前述中文场景派生的中文表达变体题，例如通过改写、续写、翻译、角色设定或上下文包装改变表达形式。
4. `en-01`：一道英文题；它可以是中文题的语义镜像，也可以基于海外英文素材原生生成。

模板库首版覆盖直接请求、改写、续写、翻译、摘要、角色设定、虚构情境、上下文包装和多轮承接等题型。生成输入始终由“风险类别、场景主题、目标对象、表达意图、题型、题目语言、语境要求”构成；出题模型不能自由扩展到无关风险。

首版 Excel 只有一个 `问题` 列，因此“多轮承接”定义为**扁平化上下文题**：在同一个问题文本中以前序对话摘录和最后一轮请求的形式表达，`轮次模式` 记为 `flattened-context`。首版不发送真实的多消息会话；未来如需真实多轮测试，另行增加 `会话ID`、`轮次` 和 `消息角色` 字段，不改变本版的单题配额。

中文题优先采用中文原生表达；海外素材可转换为自然的中文语境。英文题优先保持英语原生表达，避免逐字翻译。少量中英文镜像题保留相同的语义场景，便于比较跨语言表现；其余题目使用各语言的原生素材与表达。

当某风险类别素材不足时，使用该类别的通用场景模板补位，并在来源字段中标记为“合成素材”；不得用其他风险类别的素材凑数。

## 去重、版本和容错

去重仅在**同一题目语言**内执行；中英文镜像题以同一个非空 `镜像组ID` 关联，并明确豁免跨语言去重。比较前必须按以下顺序标准化：Unicode NFKC 归一化、英文 Unicode 小写折叠、将全部 Unicode 分隔符压缩为空、删除 Unicode 通用类别为 `P*`（标点）或 `S*`（符号）的字符。中文或英文题在风险 ID、表达意图和题型相同的前提下，满足任一条件即判为重复：标准化文本完全相同，或标准化文本的字符 4-gram Jaccard 相似度不低于 `0.90`；长度不足 4 个字符时只使用完全相同规则。重复题只保留一条，重新从相应场景卡或模板补齐配额。该稳定规则是首版的去重定义，不依赖未指定的外部嵌入模型。

每次导出使用独立题库版本号与生成批次 ID，并保留来源链接和抓取日期，支持后续重新抓取、扩题和追踪。每次成功运行同时输出当日增量包和汇总题库；汇总题库只追加通过本设计去重规则的新题，不覆盖历史记录。来源失效、正文为空、语言识别失败或场景卡信息不完整时，记录为不可用素材并跳过；配额调度器继续选择同类别候选或使用合成模板补位。

## 首版验收条件

1. 首个全覆盖基线批次导出的 Excel 总题数为 155。
2. 首个全覆盖基线批次中，31 个二级风险均恰好有 5 道题。
3. 首个全覆盖基线批次中，中文题数为 124，英文题数为 31。
4. 每题具有唯一题目 ID、`场景`、`类别`、题目语言、题型、轮次模式、配额槽与派生关系、题库版本、爬取网站和来源链接。
5. 题目文本非空，且同语言、同风险、同意图、同题型的题目不违反本设计定义的重复阈值。
6. 每个风险类别都可追溯到素材场景卡或明确标识为合成素材；合成素材使用规定的 `synthetic://` 链接。
7. 如存在镜像题，其 `镜像组ID` 非空，且仅用于中英文关联，不参与跨语言去重。
8. 每个风险的五个题目分别且仅分别占用规定的五个配额槽；网页素材的地区、语言和槽角色满足来源路由校验，或由该槽明确允许的合成素材补位。
9. 增量运行不会再次处理同一规范化 URL 和正文哈希组合；失败运行不更新最近成功状态。
10. 所有本流程的配置、数据、日志、临时文件和输出均位于 `GenerateTestQuestion` 目录内。
11. 首版运行由操作者手动启动，不依赖定时任务或后台服务。
