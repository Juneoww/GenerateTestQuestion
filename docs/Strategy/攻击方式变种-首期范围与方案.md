# 攻击方式变种全景图与首期范围

> **阅读提示：**本文保留早期调研和范围讨论，正文及附录中有关首期策略、输入面、跨会话和数量上限的建议不代表当前实现。实际范围以[一期实现设计](一期-基础规则与指令边界实现设计.md)和[实现来源](一期攻击变种-实现来源.md)为准。

日期：2026-11-13
用途：整理内容安全、LLM 应用和 Agent 测试可涉及的攻击方式，为策略选型和后续开发提供目录。本文是**全景分类与待评估清单**，并不代表这些能力已经实现或承诺全部纳入首期。已有首期建议保留在文末附录。

## 当前项目的明确边界

本功能只针对**项目现有流程已经生成的语料**做变换：先保留一条现有原题，再对其中适用的现有文本应用所选规则，形成可追溯的变种。不是重新出题，不新增目标系统调用，也不构造对话或新的测试环境。原题本身继续使用项目已有的生成流程。

目前不涉及多轮对话生成或执行，也不根据被测系统的回答调整下一条消息。OWASP 当前已有一种**跨会话记录**：`userA` 和 `userB` 分别在两个隔离会话中发送，且 `prompt` 与 `userB` 相同；这不是同一会话的多轮对话。首期保留此类原始记录，不生成其变种。

现有 Agentic 原题的 `prompt` 可能对应用户消息、工具返回等不同输入面；它仍是已有题集中的一段测试输入，不表示本工具具备 Agent 对话或工具执行功能。首期仅处理可明确确认输入面且符合附录适用条件的记录，不能改变其输入面或前置条件。

为保留之前要求的业界全景，下面第四至第八类仍作为背景参考，其中需要额外轮次、输入载体、执行器、目标环境或训练权限的条目**不属于本次基于现有语料的变种功能**，也不是已确认的后续开发计划。若某条可在不增加这些能力的情况下单独作为现有文本的变换，须明确该部分的实际适用性后才能列入候选。

## 阅读说明

业界不存在封闭且永久完整的攻击清单；本目录尽可能覆盖截至编写时可识别的主要类别和典型变体，并为新增方法预留扩展方式。不同论文和工具对同一方法的命名与分类可能不同，具体技术可以跨类别组合；不应把本目录理解为唯一的行业标准分类。

应分开记录五个维度：**测试目标**（要测什么）、**策略**（如何诱导）、**输入面**（用户、文档、工具等）、**载体／模态**（文本、图片等）、**执行方式**（单轮、多轮、自适应）。例如“工具返回中的角色伪装”是输入面和策略的组合，不是两个互斥类型。风险分类、攻击策略和实际漏洞结论不能互相替代。 [PyRIT 攻击目标与技术](https://microsoft.github.io/PyRIT/latest/code/scenarios/attack-techniques/)

目录中的实现标识：**规则**＝程序或固定模板；**模型**＝生成模型理解或改写；**环境**＝需要被测应用提供相应输入面、工具、状态或隔离夹具；**执行器**＝需要向目标发送、采集响应并维护状态；**评分**＝需要人工或判分器，结果仍可能误判。多种标识同时出现表示可以组合，并非每条都必须使用模型。

用户倾向首期只做**不额外调用模型的基础规则变种**。截图中的 `basic` 和九项规则必须纳入首期；字符间隔扰动建议一并纳入，其余基础规则待评估。模型语义改写、指令模板、多轮和 Agent 专属场景留在全景图中供后续规划，不属于当前首期建议。适用性按题目、语言和输入面判断；不适用必须记录，不能伪造变种。

这里“不额外调用模型”特指**变种阶段**：当前项目的 TC260、OWASP LLM 和 OWASP Agentic 原题生成仍使用既有模型接口，首期不改变这一流程，也不代表整次题集生成可以脱离模型。

## 一、基础变种：规则、编码和字符处理

以下方式通常可由固定算法或模板生成，不依赖生成模型。编码、替换和格式变化不保证一定构成攻击或能够绕过防护；有些变换不可逆，必须保存原题与映射。 [PyRIT 文本变换器](https://microsoft.github.io/PyRIT/latest/code/converters/text-to-text-converters/)；[Microsoft Foundry 策略列表](https://microsoft.github.io/PyRIT/latest/scanner/foundry/)。

| 编号 | 方式 | 实现方式／必要条件 | 范围 |
|---|---|---|---|
| R00 | basic 原题基线 | 保留原题，作为对照；不额外重复生成 | **首期必含** |
| R01 | Base64 | UTF-8 字节编码，可配解码任务；检查可逆性和长度 | **首期必含** |
| R02 | ROT13 | 规则变换 ASCII 字母，其他字符保留；无匹配则跳过 | **首期必含** |
| R03 | Leetspeak | 固定字母／数字／符号映射；记录版本，未匹配则跳过 | **首期必含** |
| R04 | hex 十六进制 | UTF-8 字节转十六进制，可配解码任务，检查往返 | **首期必含** |
| R05 | homoglyph 相似字符 | 固定 Unicode 映射；记录替换位置，避免破坏精确标识 | **首期必含** |
| R06 | camelcase 驼峰 | 将适用的连续英文词片段转换为驼峰形式，无适用片段则跳过 | **首期必含** |
| R07 | morse 摩尔斯 | 对支持字符按固定码表编码，保留词界；不支持的字符不静默丢弃 | **首期必含** |
| R08 | piglatin | 按固定版本对适用英文单词做 Pig Latin 转换，保留其他字符 | **首期必含** |
| R09 | emoji 不可见字符编码 | 参照 Promptfoo 将原题 UTF-8 字节编码为表情后不可见的变体选择符；需验证文本往返及导出保真 | **首期必含**；不等同可见词语替换 |
| R10 | URL／百分号编码 | 规则编码字节或字符，可指定全段或局部 | 待评估 |
| R11 | 二进制／八进制／十进制字符码 | 按字节或码点转换；明确字符集与分隔符 | 待评估 |
| R12 | HTML 实体／Unicode 转义 | 将字符变为实体或转义序列，测试解析和规范化 | 待评估 |
| R13 | 凯撒／Atbash／Vigenère | 固定替换规则；记录位移、密钥或映射版本 | 待评估 |
| R14 | 盲文／NATO 音标／其他音码 | 使用指定映射表；超出字符表时明确跳过 | 待评估 |
| R15 | 大小写扰动 | 对英文大小写按固定或可复现规则变化 | 待评估 |
| R16 | 空格／标点／分隔符插入 | 规则在适用位置插入字符，控制强度 | 首期仅建议插入空格，见附录 V10 |
| R17 | 字符删除／交换／重复／错序 | 规则或带随机种子的变换；保证标明原文 | 待评估 |
| R18 | 倒序／片段重排 | 按字符、词或片段逆序，记录作用范围 | 待评估 |
| R19 | 其他不可见字符／变体选择符 | 插入指定 Unicode 字符；保留码点、检查导出是否保真 | 后续小版本；R09 是用户确认的一期例外 |
| R20 | 变音符号／Unicode 替换 | 引入变音符号或相似编码，记录规范化前后文本 | 待评估 |
| R21 | 字符串拼接／分片 | 按规则分割、拼接或用标记隔开目标文本 | 待评估 |
| R22 | ASCII 图案／排版隐藏 | 将文本编码为文本图案或空间排版；需目标能解析 | 待评估 |
| R23 | ANSI 控制序列 | 在授权测试中插入控制序列；需保留原始字节并防止终端误渲染 | 待评估 |
| R24 | 局部／选择性变换 | 按显式区间或词表变换；保护工具名、标识符、占位符 | 待评估 |
| R10 | 繁简转换／固定转写 | 使用版本化词典或规则；转换有歧义时保留原文 | 待评估 |

Base64、hex 可用 UTF-8 覆盖中文；ROT13、Pig Latin、驼峰等主要面向英文，不能为适用而暗中翻译中文。不同规则有不同可逆性，不能一概要求往返还原；未命中或结果未变化时要明确跳过。

## 二、基于模型的语义、情境和社会工程变种

可通过模型改写或扩展上下文，亦可使用固定模板实现其中一部分。每项应保持测试目标、原题主体和关键约束；包装文本本身不意味着恶意，效果需结合目标和意图判断。

| 编号 | 方式 | 实现方式／必要条件 | 范围 |
|---|---|---|---|
| S01 | 同义改写、直接／间接问法 | 模型改句式、语气、视角，保留目标 | 后续评估 |
| S02 | 委婉、暗示、代称、词语替换 | 模型或词表改变表达，记录含义可能漂移 | 待评估 |
| S03 | 角色扮演／人格设定 | 模型生成角色和相关场景 | 后续评估 |
| S04 | 小说、剧本、游戏、假设世界 | 模型构造虚构情境 | 后续评估 |
| S05 | 研究、教育、培训、审计包装 | 模型生成情境；需保留原目标 | 后续评估 |
| S06 | 安全、防御、风险分析包装 | 模型将目标包装为防御或评估任务 | 后续评估 |
| S07 | 情绪、同情、紧急、危机场景 | 模型生成求助或紧迫情境 | 后续评估 |
| S08 | 权威、身份、职责、授权声称 | 模板或模型生成未经证实的身份声明 | 后续评估 |
| S09 | 奖励、惩罚、评测压力 | 模型或模板加入考核、积分或后果 | 待评估 |
| S10 | 第三方代问、引用、转述 | 模型转换叙述主体，保留目标 | 待评估 |
| S11 | 反问、否定陷阱、反向示例 | 模型或模板改变问题逻辑；检查是否改变目标 | 待评估 |
| S12 | 翻译、摘要、改写、校对包装 | 模型将目标置于待处理材料，区分处理数据与执行指令 | 待评估 |
| S13 | 补全、续写、填空、接龙 | 模型或模板构造不完整前文，不预泄露被测答案 | 待评估 |
| S14 | 任务分解、问题重组 | 模型拆解原目标或重组请求；单条与多轮分别标记 | 待评估 |
| S15 | 长上下文、无关材料稀释 | 规则或模型构造背景并插入目标，受上下文长度限制 | 待评估 |
| S16 | 示例诱导：零／少／多样本 | 模板或模型构造示例；多样本需标明是否模拟会话 | 待评估 |
| S17 | 时态、文体、语气、格式转换 | 模型改为过去式、口语、专业文体等 | 待评估 |
| S18 | 多语言、低资源语言、混语、音译 | 模型或翻译服务转换；记录源语言、目标语言并复核语义 | 待评估 |
| S19 | 对话历史／伪造助手回复 | 模板或模型模拟已有对话，标明真实消息角色和模拟内容 | 待评估 |
| S20 | 对抗性后缀／模板生成 | 固定种子或模型生成后缀；需目标验证才可判断效果 | 待评估 |

## 四、多轮、跨会话与自适应执行（背景参考，本次不做）

静态脚本可由模型生成；只有连接目标并根据真实响应调整，才是自适应执行。对话轮次、历史、评估与预算需独立记录。 [PyRIT 技术目录](https://microsoft.github.io/PyRIT/latest/code/scenarios/attack-techniques/)

| 编号 | 方式 | 实现方式／必要条件 | 范围 |
|---|---|---|---|
| T01 | 预设多轮分步提问 | 模型或模板生成有顺序的多条消息；需要会话状态 | 待评估 |
| T02 | 渐进式升级／Crescendo | 模型构造递进对话；动态形式需执行器与反馈 | 待评估 |
| T03 | 上下文铺垫与延迟触发 | 多轮建立语境、约定或延迟任务；需保存历史 | 待评估 |
| T04 | 拒绝后的追问和改写 | 规则或模型根据回复续问；需执行器 | 待评估 |
| T05 | 分支对话、自适应红队 | 模型生成候选，执行器按响应选择下一步 | 待评估 |
| T06 | PAIR／TAP | 使用攻击模型、目标反馈及评分；TAP 另有树搜索和剪枝。迭代优化不一定意味着目标端处于同一多轮会话 | 待评估 |
| T07 | Best-of-N 多候选搜索 | 规则或模型批量生成，执行器及评分筛选；需预算和停止条件 | 待评估 |
| T08 | 多轮扮演／模拟历史 | 生成消息序列或模拟历史；标识真实轮次和文本伪造 | 待评估 |
| T09 | 跨会话、跨用户隔离 | 使用独立会话和虚构测试数据，观察信息是否越界 | 待评估；项目已有原题能力，变种暂不纳入首期 |
| T10 | 持久化记忆、延迟再次访问 | 设置写入阶段与后续触发阶段；需可重置记忆环境 | 待评估 |

| D02 | RAG 文档与检索结果投毒 | 构造隔离语料和检索结果，观察来源边界及回答 | 待评估 |

| D05 | 代码、注释、README、提交和问题描述 | 建立测试仓库并经目标的仓库读取入口使用 | 待评估 |
| D06 | 数据库记录、日志、配置、业务对象 | 预置低可信测试数据，观察是否被提升为指令 | 待评估 |
| D07 | 工具返回、API 响应、报错 | 使用可控测试桩返回内容，并记录实际调用 | 待评估 |
| D08 | 标签、标题、元数据与隐藏文本 | 构造可解析但不一定可见的内容，确认解析路径 | 待评估 |
| D09 | 引文污染、虚假来源、证据伪造 | 构造文档或引用并检查回答和来源归属 | 待评估 |
| D10 | 持久检索库与数据集污染 | 控制测试索引或语料生命周期；评估检索与后续影响 | 待评估 |
| D11 | 检索排序操纵和来源冒充 | 控制测试文档与检索条件，观察结果排序和来源验证 | 待评估 |

| D13 | 输出渲染／下游处理注入 | 使用隔离测试页面或下游解析器，检查模型输出进入渲染、查询或命令等环节后的处理；需实际链路证据 | 待评估 |

## 六、Agent、工具、权限与多智能体（背景参考，不新增执行环境）

这一类按攻击的运行环境组织，部分项目是**风险目标或场景**，不只是文本变换。要配虚构数据、最小权限、可重置夹具并观察调用和实际状态；无法取得证据的层次标记不可判定。 [OWASP Agentic Top 10](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/)

| 编号 | 方式／场景 | 实现方式／必要条件 | 范围 |
|---|---|---|---|
| A01 | 目标劫持与计划偏移 | 用户输入或低可信上下文诱导偏离原任务；比较任务和计划 | 待评估 |
| A02 | 工具选择诱导 | 构造请求或工具说明，观察选择的工具及目的 | 待评估 |

| A13 | 过度自主、循环调用、资源消耗 | 在有预算与停止机制的环境观察调用次数与退出行为 | 待评估 |

# 附录：历史首期方案（已被后续设计取代）

本附录保留早期讨论记录，其策略、图片和范围描述可能与用户后续选择冲突；当前范围以[一期实现设计](./一期-基础规则与指令边界实现设计.md)及[开源实现调研](./一期攻击变种-开源实现调研.md)为准。

日期：2026-11-13
状态：讨论稿，供确认范围；尚未实施。

## 1. 目标与边界

在现有三类题集（TC260 内容安全、OWASP LLM、OWASP Agentic）生成原题后，按用户选择的攻击策略生成可追溯的测试变种。原题是对照基线；策略是对测试输入的处理，不改变风险分类。交付物是待验证的测试候选，生成成功不代表变种有效或被测系统存在漏洞。

首期限定为**基础规则、文本输入、单条静态变种、单种策略**。变种及其校验由本地规则完成，不额外调用模型，也不连接被测系统执行攻击；原题仍按项目现有流程调用模型生成。优先支持能够明确识别输入位置且不改变测试前置条件的题目。

## 2. 首期纳入的策略

用户要求截图中的 `basic`、`Base64`、`ROT13`、`Leetspeak`、`hex`、`homoglyph`、`camelcase`、`morse`、`piglatin`、`emoji` 均纳入首期。`basic` 是原题基线，保留一次，不作为额外变种或额外数量；其余九项为本地规则变种，不调用模型。截图中的多轮列不视为本次增加多轮能力的要求，本期仍限定单条静态输入。

| 编号 | 策略 | 生成方式 | 首期处理规则 |
|---|---|---|---|
| V09 | Base64 编码 | 程序规则 | 使用 UTF-8 编码原输入，再以明确的解码与处理请求包装；保留编码前原题。 |
| V10 | 字符间隔扰动 | 程序规则 | 使用固定强度在适用文本片段中插入空格；若不适用或结果不变则跳过。 |
| V11 | ROT13 字母轮转 | 程序规则 | 对 ASCII 英文字母执行 ROT13，其余字符保持不变；不含可变换字母或结果无变化时跳过。 |
| V12 | Leetspeak 字符替换 | 程序规则 | 按版本化字母到数字或符号的固定映射替换，保留未映射字符；无可替换字符时跳过。 |
| V13 | hex 十六进制编码 | 程序规则 | 原输入先转 UTF-8 字节再转十六进制，附明确的解码与处理请求；支持中英文，保留原文。 |
| V14 | homoglyph 相似字符混淆 | 程序规则 | 按固定的 Unicode 相似字符映射表替换适用字符；无匹配字符时跳过，记录映射版本。 |
| V15 | camelcase 驼峰式变换 | 程序规则 | 对含两个及以上适用 ASCII 英文单词的连续片段按固定规则合并为 lowerCamelCase，其他片段保留；没有适用片段时跳过。 |
| V16 | morse 摩尔斯编码 | 程序规则 | 对支持字符表内的输入按固定国际摩尔斯映射和分隔符编码，并附解码与处理请求；含不可编码字符时整条跳过，不静默丢弃。中文原文默认不适用。 |
| V17 | piglatin 文字变换 | 程序规则 | 对 ASCII 英文单词应用固定版本的 Pig Latin 规则，保留标点及其他字符；无适用单词时跳过。 |
| V18 | emoji 表情符号变换 | 程序规则 | 使用版本化的固定词语到表情映射替换明确匹配的词语，其他内容保留；无匹配时跳过。记录映射和替换位置；表情存在歧义，标记待人工复核，不声称可逆或语义等价。 |

保留原编号以便追溯，V01–V08 已移出首期，并非编号遗漏。上述 V09–V18 在本地执行，变种生成和校验不额外调用模型。V10 字符间隔扰动为建议项，是否纳入待确认；其余九项为用户要求。不同策略的有效性取决于被测模型、输入链路与上下文，不预设成功率。

本期不加入翻译或混合语言策略：当前三类生成器已有语言约束，增加跨语言变换涉及语义保真与配额定义，留待单独设计。规则变换使用固定版本和明确映射，不做不可见字符或随机扰动。各规则完整映射表、大小写、分词及边界字符处理应在实施设计中明确并纳入测试；不能静默改变原文中的工具标识、密钥标记等精确匹配字段。

## 3. 三类题集的适用范围

| 题集／形式 | 首期范围 | 约束 |
|---|---|---|
| TC260 文本对话题 | V09–V18，V10 待确认 | 保留风险小类、语言、来源与素材情境关联。 |
| TC260 图片生成题 | 不适用 | 面向文生图模型的提示词与对话攻击不同，暂不套用文本策略。 |
| OWASP LLM | V09–V18，V10 待确认；限单消息、明确以用户消息为输入的题目 | 不适用跨会话、外部内容注入或输入面不明确的记录。 |
| OWASP Agentic | V09–V18，V10 待确认；限单消息、明确以用户消息为输入的题目 | 保留任务、身份、权限、工具、输入面和断言；不能把外部内容或工具输出改称用户消息。 |

适用性按**每条原题及策略**判断，而不是按风险编号一刀切。TC260 以现有文本对话题类型确认；OWASP 与 Agentic 仅当现有信息能明确确认输入面为单条用户消息，且该策略不破坏目标、环境或断言时才处理；无法确认则跳过并记录原因。现有数据不足以可靠判断时不得猜测，具体可判定字段和支持范围在实施设计中核实。

OWASP 的跨会话记录本期完整保留为原题，不生成变种；其 `userA`、`userB` 和 `prompt = userB` 关系不改变。已有文字图片功能仍可用于原题；本期不为变种生成文字图片，也不将现有渲染能力当作多模态攻击覆盖。

## 4. 建议交互及数量口径

以下为首期建议，等待用户确认：

1. 在三个生成页提供“生成攻击方式变种”开关，默认关闭；关闭时生成、导出及数量行为与现有版本一致。
2. 开启后可多选第 2 节的策略；图片生成题不提供此选项。所选策略的适用性在执行时逐条判断。
3. 现有数量 N 指**原题数量**。对每道适用原题，每种所选策略最多生成 1 条变种；原题保留，因此理论总数为 N ×（1 + 所选策略数）。跳过或失败会减少实际变种数，界面显示原题、理论上限、成功、跳过与失败数量。
4. 生成前显示预估数量并说明规则变种不额外调用模型；原题生成仍按现有方式调用模型。设置总变种数量上限，建议首期最多 1000 条；超限时阻止开始并提示调整。
5. 每条变种仅使用一种策略，不自动组合；同一个策略生成一条，不设置额外的每策略数量。

用户还没有选择数量口径；上述 N 为原题数量及每策略一条均为方案建议，而非已确认需求。

## 5. 处理流程与质量控制

1. 按现有流程生成、验证原题；逐条判定所选策略是否适用。
2. 规则策略按固定版本在本地转换，不调用生成模型或被测系统。
3. 校验结果非空、不同于原题、无明显重复、符合对应输入及规则约束；本地检查无法保证风险、对象、关键条件和原有断言语义不变。语义存在不确定性时，可在结构及断言确定的前提下明确标为待人工审核，否则跳过；不得宣称验证通过。
4. 规则不适用或生成错误时记录原因，不以原题冒充变种。保留原题及成功变种，并给出失败／跳过清单。用户停止时继续遵守现有取消与未发布批次撤回行为。
5. 在最终顺序确定后，再按最终记录构建 OWASP 评测与行号映射；如果无法为变种生成与其输入面一致的检查项，该变种不纳入结果。输出文件按现有批次的暂存与发布机制处理。

现有 TC260 长度、语言和去重规则及 OWASP 六字段、语言、风险和 Agentic 质量规则均需评估是否适用于变种。Base64、hex 和 morse 会改变语言字符比例和长度：先按既有规则校验原题，再分别校验编码可逆性、包装结构和最终输出长度；不得将编码文本未通过自然语言比例检查当成语义验证通过，也不得为了通过校验静默裁剪编码内容或弱化原题检查。其他替换规则也须检查可读性与关键字段保持；需要调整变种专用校验时必须单独设计并覆盖回归测试；不满足既有长度或其他输出约束时明确跳过并记录原因。

## 6. 结果与兼容性

- 原题先于其变种展示；每条变种可追溯到原题、策略和状态。记录策略编号、版本、实现类型、参数、原题标识及输出记录位置；固定规则和映射应可复现。
- OWASP 的题库 JSON 和 Excel 保持 `riskId / riskName / userA / userB / prompt / assertion` 六字段契约；关联和策略信息写入批次独立元数据文件，以最终结果行号关联。图片列继续遵循现有可选规则。
- TC260 保留已有题库字段、来源和风险信息；关联信息也优先放入独立元数据文件，避免未经评估改变现有消费者契约。
- 元数据至少记录所选策略、版本、原题与变种的最终行号、结果状态及失败或跳过原因；不得记录 API Key。历史批次不强制迁移，没有元数据时仍可按原方式读取。
- 原断言只有在仍准确描述变种的输入面和预期行为时才能沿用；无法确认时不输出该变种。变种不是对系统安全性的判定结果。

## 7. 本期不做

- 多轮对话、自适应攻击、目标系统连接、自动评分和攻击成功率统计。
- 跨会话变种；外部文档、网页、检索、工具返回、Agent 间通信和记忆等输入面的新测试夹具。
- 文生图题变种，以及新增图片、音频、视频或 PDF 攻击载体。
- 基于模型的语义改写、角色扮演和场景包装；指令覆盖、身份伪装与回答格式等规则模板也暂不纳入本期。
- 翻译、混合语言、不可见字符、多策略组合及其他尚未列入第 2 节的策略。
- 自动宣称模型改写保持语义，或宣称变种能成功绕过任何防护。

## 8. 验收标准

1. 默认关闭时，现有三类生成、结果和导出行为保持兼容；旧批次可读取。
2. 对适用原题，所选每项策略最多得到一条独立变种；保留原题，数量和状态可核对。
3. 不适用、失败、无变化或重复结果不会被计作成功，且能追溯原因；取消行为符合现有批次规则。
4. 逐项测试截图要求的全部规则、中文和英文、空值、不适用、映射边界及可复现性，对可逆编码进行往返测试；`basic` 不重复生成；验证变种阶段不调用模型接口。
5. 三类题集分别验证风险、来源或输入面保持；跨会话和文生图题不会被错误处理。
6. OWASP 题库六字段不变，评测行号和变种关联与最终结果一致；导出及历史批次读取通过回归检查。
7. 界面与文档说明原题仍依赖模型、变种阶段不额外调用模型，以及适用范围和候选结果的限制；不以生成成功代替人工或目标系统验证。
