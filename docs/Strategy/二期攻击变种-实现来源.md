# 二期攻击变种：实现来源

本文记录二期代码实际使用的规则与来源。变种基于既有原题，由本地代码执行，不调用模型或被测系统，也不引入词汇表或额外映射表。

| 策略 | 实际方法 | 代码来源 |
|---|---|---|
| R17_repeat／swap／delete | 按固定下标重复、交换或删除 Unicode 码点 | 本项目实现，使用 Python 字符串操作。 |
| R19_zwsp | 在相邻字母或数字间插入 U+200B | 本项目实现，使用 Python 标准库 `unicodedata.category` 判定字符类别；不是 Promptfoo 的 R09 方法。 |
| R20_fullwidth | 将 U+0021–U+007E 的字符码点加 `0xFEE0` | 本项目实现，使用 Python 的 `ord`、`chr`；没有字符替换表。 |
| R21_chunks | 固定长度分片，序列化为 JSON 数组并加入固定拼接提示 | 本项目实现，使用 Python 标准库 `json`；提示模板为本项目编写。 |
| R24_partial_base64 | 对固定的中间片段按 UTF-8 编码后做 Base64，使用 JSON 保存前缀和后缀 | 本项目实现，使用 Python 标准库 `base64`、`json`；提示模板为本项目编写。 |

上述二期策略没有复制或移植第三方项目代码。一期 R09 仍使用移植自 **Promptfoo 0.125.1** 的 `toEmojiEncoding`，具体源码链接与许可证记录见[一期实现来源](./一期攻击变种-实现来源.md)和项目根目录 `THIRD_PARTY_NOTICES.md`。未部署整个 Promptfoo。

输出状态为生成成功只表示完成了规定的文本变换，不表示语义完全不变或攻击已成功。R17 尤其可能改变原题含义，原题应与变种对照复核。
