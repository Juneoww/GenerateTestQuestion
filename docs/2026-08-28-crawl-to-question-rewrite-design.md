## 1. 背景与问题

现有桌面端有四个工作区（一键生成、语料采集、来源配置、高级维护），与核心诉求"爬取网站 → 生成题目"脱节：

- 人工素材入库、去标识化提取等流程对当前需求是冗余负担；
- 题目生成依赖模板合成补位，"一眼假"，质量上限低；
- 来源登记表（15 站 124 路由 xlsx + V0–V3 门禁体系）维护成本高，而实际可自动运行的来源很少；
- 架构割裂：Python UI 调 Node 子进程，Excel 读写还依赖 `@oai/artifact-tool`（本机 codex 运行时私有包），项目离开当前机器无法部署。

## 2. 目标与非目标

**目标**

1. 把工具收敛为单一流程：选择网站 → 选择题目类型 → 设置数量与中英文比例 → 配置模型 → 生成题目；
2. 题目为**测试提示集**：只有题干，不含选项、答案、解析；
3. 提供实时日志显示，以及"依据的原文 ↔ 生成的题目"对照视图；
4. 建立可维护的来源管理：收集可爬取网站，**自动核验通过即进入可用清单（无人工确认环节）**；
5. **全过程留痕**：来源名单、核验记录、每次爬取的记录与内容、生成记录均落盘可查（见第 7 节）；
6. 实现可交付：**纯 Python 单栈**，`pip install` 即可部署，无需 Node.js 与任何私有依赖。

**非目标（本期不做）**

- 评测判分、合格率报告；
- 训练/微调语料管线（正负样本语料集）；
- 多用户、联网服务化。

## 3. 已拍板决策

| 决策点 | 结论 | 说明 |
|---|---|---|
| 题目形态 | 只有题干，无答案 | 用途是测试提示集，测 AI 是否输出风险内容 |
| 题目类型口径 | 参照 TC260-003，大类→小类两级联动，小类可多选 | 5 大类 → 31 小类，数据来自 `risk_catalog.json` |
| 出题模型 | OpenAI 兼容接口（base_url + API Key + 模型名） | DeepSeek/智谱/通义/Kimi/OpenAI 等均可接入 |
| 爬取引擎 | **Scrapling 统一引擎，纯 Python 单栈** | 默认 `Fetcher`（TLS 指纹伪装）；困难站点按需 `StealthyFetcher`；Node 层整体删除 |
| 来源可用判定 | 自动核验通过即可用，无人工确认 | 「核验」探测 HTTPS 可达与条目可提取，通过即"可爬" |
| 过程留痕 | 每个环节产出可查文档与记录 | 网站名单、核验日志、每次爬取的记录与内容、生成记录（见第 7 节） |
| 旧功能去留 | 语料采集、高级维护（人工素材）、来源登记表**彻底删除** | 含全部 Node 服务与旧测试；git 历史可恢复 |
| 旧批次数据 | 移入 `data/_legacy/` 归档 | 不参与新管线，界面与代码不再引用 |
| 输出格式 | Excel + JSON 双输出 | 界面内同时提供原文↔题目对照预览 |
| 批次 ID | 自动生成（`BATCH-YYYYMMDD-HHMMSS`） | 不再要求用户填写 |

## 4. 界面设计（三页）

### 4.1 生成页（默认主页）

**参数区（自上而下）**

1. 网站多选下拉：仅列出「可爬」状态的站点，附语言标注；
2. 题目类型两级联动：一级下拉选大类（可多选），二级联动列出所选大类下的 31 小类（可多选）；
3. 生成数量（整数，下限 = 所选小类数）与中文占比（0–100）；
4. 「开始生成」按钮：运行期间禁用，防止并发运行。

**日志面板**：文本区实时滚动追加。事件包括：每个站点的爬取请求与结果（条数、失败原因）、每道题的生成进度（如 `12/50`）、重试、校验失败、导出路径。事件由工作线程经队列推送到主线程。

**原文 ↔ 题目对照区**：左侧为本次批次题目列表（序号 + 题干摘要），点选后右侧显示：题干全文、语言、大类/小类、依据原文摘录（含来源站点与 URL，可点击在浏览器打开原文）。

### 4.2 来源管理页

站点清单表格，列：来源 ID、名称、URL、语言、采集方式（HTML/JSON）、引擎（fetcher/stealthy）、状态、最近核验时间、备注。

- 状态机：`待核验 → 可爬 / 失败`，另有手动「停用」；**自动核验通过即"可爬"，直接进入生成页下拉，不设人工确认环节**；
- 「核验」按钮：对选中（或全部）站点执行自动探测——HTTPS 可达、页面结构 / JSON 接口返回规整、能提取出条目；成功置"可爬"，失败置"失败"并记录原因；每次核验写入核验日志并刷新网站名单；
- 「停用」：手动屏蔽某站点，不参与核验与生成；
- 「新增站点」：填写名称、URL、语言、采集方式、条目提取规则与引擎后加入清单（先置"待核验"）。

来源清单持久化为 `data/sources.json`。

### 4.3 设置页

- 模型配置：接口地址（base_url）、API Key、模型名、（可选）温度与超时；「测试连接」按钮发一条最小请求验证连通性并回显模型响应；
- 配置持久化为 `data/settings.json`——**含 API Key，必须保持在 .gitignore 内**；
- 其他默认参数（请求超时、单题重试次数、单条原文最多出题数、爬取请求间延时）以默认值展示，允许修改。

## 5. 架构与技术方案

### 5.1 纯 Python 单栈

```
┌─ Python 单栈（app.py + 模块）─────────────┐
│ Tkinter 三页 UI / 日志队列 / 批次编排      │
│ 爬虫：Scrapling Fetcher（默认）            │
│       StealthyFetcher（按需，困难站点）    │
│ LLM 调用（urllib，OpenAI 兼容 /chat/completions）│
│ Excel 导出（openpyxl）                     │
└──────────────────────────────────────────┘
```

- **依赖**：`pip install "scrapling[fetchers]" openpyxl`；仅在首个需要浏览器抓取的站点出现时执行一次 `scrapling install` 下载浏览器组件。
- **环境**：Python ≥3.10（本机 3.13 满足）；不再需要 Node.js，`tools/` 目录与 `node_modules` 符号链接整体移除。
- 爬取与出题在工作线程执行，UI 经队列接收事件，无子进程协议。

### 5.2 LLM 出题

- 提示词结构：系统消息说明 TC260 小类定义与出题要求（基于给定原文素材、贴合真实情境、输出该小类的诱导性测试问题、指定语言）；用户消息为原文摘录；要求以 JSON 数组返回（字段：`question`、`language`）。
- 校验：JSON 解析、非空、语言启发式校验（CJK 字符占比）、内容哈希去重（跨批次）；失败按设置重试（默认 2 次），仍失败跳过并记入日志与批次缺口。
- 数量分配：总量按中英文比例拆分后，在所选小类间轮转分配；**不做合成补位**，配额不满时如实报告缺口。
- 限速与成本：单条原文最多出题数默认 5；请求间礼貌延时；连续失败熔断。

### 5.3 爬虫行为要求（继承旧实现并修复缺陷）

Scrapling 提供抓取与解析能力，以下门禁与纪律由新爬虫层自行实现：

| 要求 | 说明 |
|---|---|
| HTTPS 门禁 | 仅 `https://`（默认 443、无凭据）的来源可进入清单；核验与爬取前统一校验 |
| 同域限制 | 列表页解析出的详情链接限同域，跨域链接丢弃并记录 |
| 礼貌限速 | 每个请求之间执行延时（默认 500ms，可配置）——修复旧 Node 版"限速只生效一次"的缺陷 |
| 超时与大小 | 请求超时（默认 15s）；响应优先校验 Content-Length，超过上限（默认 2 MiB）拒绝并记录 |
| 留痕 | 每条抓取内容按第 7 节按批次落盘；重定向后的最终 URL 记入条目 |
| 引擎选择 | 默认 `Fetcher`；来源配置 `engine: "stealthy"` 时改用 `StealthyFetcher`（需已执行 `scrapling install`） |

### 5.4 日志事件流

爬取与出题在工作线程执行，通过 `queue.Queue` 投递结构化事件（阶段、站点、消息、计数）；Tk 主线程 `after` 轮询队列刷新日志面板与进度；全部事件同步写入批次目录 `run.log`。

## 6. 数据模型

### 6.1 `data/sources.json`（来源清单）

```json
{
  "formatVersion": 1,
  "sources": [
    {
      "sourceId": "PIYAO",
      "name": "中国互联网联合辟谣平台",
      "url": "https://www.piyao.org.cn/",
      "language": "zh",
      "method": "html",
      "listUrlTemplate": "https://www.piyao.org.cn/list{num}.htm",
      "itemPattern": "<a[^>]*href=\"([^\"]+)\"[^>]*>",
      "engine": "fetcher",
      "status": "ready",
      "lastCheckedAt": "2026-08-28T12:00:00Z",
      "note": ""
    }
  ]
}
```

状态取值：`pending`（待核验）/ `ready`（可爬，自动核验通过）/ `failed`（核验失败）/ `disabled`（手动停用）。`engine` 取值 `fetcher`（默认）/ `stealthy`。

### 6.2 `data/risk_catalog.json`（风险目录）

5 大类 + 31 小类（sceneCode、riskId、名称、说明），由旧 `build_source_registry.mjs` 中的硬编码数据一次性提取生成，作为两级下拉与 LLM 提示词的唯一数据源。

### 6.3 `data/settings.json`（设置，含 API Key，不入库）

`baseUrl`、`apiKey`、`model`、`temperature`、`timeoutSeconds`、`retries`、`maxQuestionsPerItem`、`crawlDelayMs`。

### 6.4 批次输出 `data/output/<批次ID>/`

| 文件 | 内容 |
|---|---|
| `questions.json` | 全量题目（含完整原文摘录与元数据，供对照区读取） |
| `questions.xlsx` | 对外交付版，列：序号、题干、语言、大类、小类、来源站点、来源 URL、原文摘录（截断 500 字）、批次、生成时间、模型 |
| `run.log` | 全量日志 |
| `manifest.json` | 参数（站点、小类、数量、比例、模型）、实际产出统计、缺口报告 |

爬取内容与过程报告见第 7 节，同样按批次目录归档。

## 7. 过程留痕与文档产物

**每个环节都必须留下可查阅的文档与记录**，全部落在 `data/`（不入 git，仅存本地）：

| 环节 | 产物 | 路径 | 内容 |
|---|---|---|---|
| 来源核验 | **网站名单**（人读，常新） | `data/reports/网站名单.md` | 每站名称、URL、语言、采集方式、状态、最近核验时间、最近一次爬取摘要；每次核验后自动重新生成 |
| 来源核验 | 核验日志（追加式） | `data/reports/核验日志.md` | 每次核验：时间、站点、各探测项结果（HTTPS 可达/结构规整/条目提取数）、失败原因 |
| 爬取 | **爬取记录与内容** | `data/output/<批次>/crawl/<sourceId>/items.jsonl` | 每条被抓内容逐行保存：URL、标题、正文全文、抓取时间、HTTP 状态、内容哈希 |
| 爬取 | 爬取报告 | `data/output/<批次>/crawl_report.md` | 本次各站请求页数、抓到条数、去重数、成功/失败与耗时汇总 |
| 出题 | 生成记录 | `data/output/<批次>/questions.json` | 题目全文 + 依据原文 + 来源 URL 对照（界面对照区数据源） |
| 出题 | 模型调用记录 | `data/output/<批次>/llm_calls.jsonl` | 每次模型调用：时间、模型、对应原文条目、返回题数、校验结果、耗时 |
| 全程 | 运行日志 / 批次汇总 | `run.log`、`manifest.json` | 全量日志文本；批次参数、产出统计、缺口报告 |

说明：旧方案对原始全文"不落盘"，本节按新需求改为**爬取内容按批次落盘留存**；`data/output/` 与 `data/reports/` 均在 .gitignore 范围内，不进公开仓库。
