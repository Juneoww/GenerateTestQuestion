# 合格率语料集设计与采集方案（TC260-003 9.2 语料安全评估）

## 1. 目标

建立一套**带真值标签的合格率语料集**，用于 TC260-003《生成式人工智能服务安全基本要求》9.2 语料安全评估的评估工具校准与抽检演练：

```text
公开采集源（15 站登记 + 公开敏感词库 + 中英文）
  → Scrapling 采集层（RSS/Sitemap 优先 → Fetcher → 降级渲染）
  → 规范化与去重（去标识化、内容哈希、长度过滤）
  → 风险标注（覆盖附录 A 全部 31 类 + 正常负样本，人工+模型双轨）
  → 合格率语料集（正样本 31×200 + 负样本 ≥4000，每条含真值标签与来源）
  → 关键词库/分类模型校准（9.2c、8.1、8.4）+ 人工抽检流程演练（9.2a）
```

## 2. 标准依据（与原文逐条对齐）

| 条款 | 原文要求 | 对本设计的约束 |
|---|---|---|
| 3.4 抽样合格率 | 抽样中不包含附录 A 所列出 31 种安全风险的样本所占的比例 | 合格率统计口径：逐条判定"是否含 31 类风险"，语料集真值标签必须支持该判定 |
| 9.2 a) 人工抽检 | 从全部语料中随机抽取不少于 4000 条语料，合格率不应低于 96% | 负样本池起步 ≥4000 条，支撑抽检演练 |
| 9.2 b) 技术抽检 | 结合关键词、分类模型等技术抽检，从全部语料中随机抽取不少于总量 10% 的语料，抽样合格率不应低于 98% | 正样本必须 31 类全覆盖且可被关键词/分类模型命中，用于验证工具召回 |
| 9.2 c) 评估工具 | 评估采用的关键词库、分类模型应符合本文件第 8 章要求 | 语料集承担"工具校准验证"职能 |
| 8.1 关键词库 | 总规模不宜少于 10000 个；至少覆盖 A.1 及 A.2 共 17 种，A.1 每类不宜少于 200 个，A.2 每类不宜少于 100 个 | 每类正样本 ≥200 条（用户已拍板），足以验证对应关键词的命中与误报 |
| 8.4 分类模型 | 应完整覆盖本文件附录 A 中全部 31 种安全风险 | 语料集 31 类全覆盖，作为分类模型准确率验证集 |
| 5.3 d) 标注隔离 | 宜对安全性标注数据进行隔离存储 | 风险正样本与正常负样本分区存储，标注数据单独管理 |

**关键结论（标准核对）**：标准未定义"合格率语料集"概念，9.2 的评估对象是被测服务提供者的**全部训练语料**。本语料集的正确定位是：**评估工具（关键词库、分类模型）的带真值校准/验证集**，兼作 9.2 人工抽检流程的演练样本池。它不是被测语料本身，不替代 9.2 对被测方语料的抽检。

## 3. 范围与边界

### 3.1 纳入范围

- 采集公开、无需登录的页面与公开数据集；来源限定为来源登记表（`source_registry.xlsx`）已核验网站 + 经人工审核的公开敏感词库。
- 正样本 31 类全覆盖，每类 ≥200 条；负样本（正常语料）≥4000 条；中英双语（启用 S09–S15 英文来源）。
- 输出：`data/corpus/<批次>/` 原始语料 JSONL + 真值标注视图（Excel/JSON）+ 批次清单。

### 3.2 不纳入范围（合规红线）

- 不绕过登录、付费墙、验证码、反爬挑战或访问控制；不使用代理轮换、指纹伪装、Cloudflare/Turnstile 绕过、验证码求解。
- **不落原始违规全文**：风险样本只保存通报/案例原文、词库词条、特征化改写文本；不含当事人身份、账号、联系方式（对齐 S07/S08 既有去标识化要求）。
- 敏感词库仅选用公开且许可允许再分发/使用的（如 Apache-2.0、MIT）；不采集他人明确声明不可采集的语料（对齐 5.1 c) 2)）。
- 语料集不直接作为题库输入；与现有 `data/question_bank/`、`data/source_items.xlsx` 保持独立。

每条语料记录（JSONL 一行一条）：

```json

  "risk_id": "A1-01 | SAFE",

  "scene": "违反社会主义核心价值观的内容",
  "text": "特征化/通报/词条文本，原始违规内容不落盘",
  "source_url": "https://…",
  "source_id": "S01",
  "language": "zh | en",
  "label_method": "manual | model | official_case | lexicon",
  "label_status": "draft | reviewed",
  "content_hash": "sha256…",
  "batch_id": "CORPUS-20260828",
  "collected_at": "2026-08-28T10:00:00Z"
}
```

落盘布局：

```text
data/corpus/
  corpus_master.xlsx            # 真值标注视图（风险目录/正样本/负样本/清单四表，规划中）
  negative_sources.json         # 负样本来源配置（可增删源控制中英比例）

    positive_items.jsonl        # 风险正样本（隔离存储）
```

## 6. Scrapling 使用边界

| 用途 | 能力 | 说明 |
|---|---|---|
| 静态公开页 | `Fetcher` / `AsyncFetcher` | 普通 GET + 超时 + 限速 + 有限重试 |
| JS 渲染页 | `DynamicFetcher` | 仅普通抓取无正文时启用，不启用隐身/挑战绕过 |
| 链接发现 | `LinkExtractor` / `CrawlSpider` | 限定登记域名、路径规则、最大深度 |
| RSS/Sitemap | `XMLFeedSpider` / `SitemapSpider` | 优先于栏目页扫描 |
| 正文提取 | `Response.markdown(main_content_only=True)` | 去除脚本/样式/导航 |
| 明确不用 | 代理轮换、指纹伪装、反 Cloudflare、验证码求解 | 与既有设计文档一致 |

## 7. 标注与真值管理

- 双轨标注：模型预标注（关键词宽筛 + 分类模型）→ 人工审核；**每条安全性标注至少经一名审核人员审核通过**（对齐 5.3 c) 2)）。
- 正样本准入校验：`risk_id` 属于 31 类目录；文本可被库内关键词或分类模型命中；`source_url` 非空且可回指。
- 负样本准入校验：不含 31 类风险（模型 + 人工抽检双确认）；来源为官方新闻/科普/政务公开等正常渠道。
- 标注数据与原始采集数据隔离存储（对齐 5.3 d)）。

## 8. 产出校验（成功标准）

1. 正样本每类 ≥200 条、31 类全覆盖；负样本 ≥4000 条；中英文按批次参数分配。
2. 每条含非空 `risk_id`（或 SAFE）、`source_url`、`content_hash`、`label_status=reviewed`。
3. 去重：`content_hash` 全局唯一；同来源同文本不重复入库。
4. 违规原文不落盘：风险样本文本形态仅限通报/案例原文、词条、特征化改写。
5. 配额不足时严格失败：只产出缺口报告，不发布语料集。

关键机制：

- **语言配额分配**：`splitLanguageQuota(total, zhPercent)` → 中文 `Math.round(total * zhPercent / 100)`，英文取余。
- **HTML 列表直采（无需 JSON API）**：`fetchHtmlContexts` 按 `listUrlTemplate` 的 `{num}` 通配符翻页（支持路径式 `list{num}.html` 与查询式 `?page={num}`）→ `itemPattern` 正则提取文章链接 → 逐条抓详情页提取 `<title>` + 正文纯文本（截断 600 字符）→ 产出 `{title, description, sourceUrl}`；单条详情失败仅跳过不中断；`source_url` 回指详情页。
- **正文提取去噪**：标签转行后按行清理——短行样板关键词（搜索/登录/首页/当前位置等）与面包屑（`>>`/`›`）整行丢弃、与 `<title>` 重复的行（head/h1）丢弃、连续重复行丢弃、行内空白压缩；正文摘要不再保留标题副本。
- **正文提取去噪（v2，2026-08-28 升级）**：`pickMainRegion` 优先提取 `<article>` 区域（Full Fact/Snopes/FTC 均适用，导航菜单天然排除），其次 `<main>`，无则回退整页（12377 中文站，行为不变）；标签转行后按行清理——中文短行样板关键词（搜索/登录/首页等）、**英文导航/菜单噪声行（Menu/Donate/Articles/Latest/Fact checks/主题词等精确匹配）、站点描述句（"Everything we publish…"/"Browse our fact checks…"前缀匹配 ≤160 字符）、面包屑/作者/分享元信息行、`&bull;` 分类/阅读时长元信息行**、与 `<title>` 重复的行（head/h1）丢弃、连续重复行丢弃、行内空白压缩；正文摘要不再保留标题副本。英文批次导航噪声实测降为 0。
- **关键词自动归类（大小写不敏感）**：`classifyHtmlItem` 先小写化再子串匹配，`risk_classifier.json` v2 中英文关键词并存；HTML 来源按 `sourceId` 独立配额（不占用 JSON 路由的 riskId×语言配额），缺口按来源记录。
- **跨批次哈希去重的运维操作**：批次重采前须用 `.purge-hash.mjs` 备份并删除对应 batchId 的旧哈希（正文提取规则变更会改变内容哈希，否则重采全部被去重跳过）。
- **合规红线（复用既有机制）**：仅提取白名单字段/标题+摘要，原始响应全文不落盘；风险样本只存通报/案例原文、词条、特征化改写文本。
- **诚实失败**：配额不足时产出缺口报告并如实记录，不伪造语料。
