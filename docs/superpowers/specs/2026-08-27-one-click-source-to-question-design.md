# GenerateTestQuestion 一键来源到题库设计

## 用户目标

日常使用不再手工填写原文、授权证据、事实要点或风险触发点。用户只需选择网站，设置题目数量和中英文比例，然后获取题库 Excel。

## 日常界面

### 一键生成（默认页）

页面只展示三块内容：

1. **网站选择**：按网站而非风险路由显示来源卡片；可全选、按语言筛选或逐个选择。卡片展示来源语言、覆盖风险数、采集状态与最近一次结果。
2. **风险场景选择**：五个一级类别使用多项复选框，默认全选：违反社会主义核心价值观、歧视性内容、商业违法违规、侵犯他人合法权益、无法满足特定服务类型的安全需求。
3. **生成参数**：题目总数、中文占比、运行日期、批次 ID。默认总数为 155、中文占比为 80%。
3. **运行结果**：显示本次已采集网站数、可用上下文数、补位题数、各语言题数和两个 Excel 输出路径。

主按钮为“开始采集并生成题库”。日常用户不需要进入任何素材表单。

### 高级维护（非默认页）

保留既有“人工素材入库与提取”能力，仅作为无法自动采集时的维护入口。原有授权字段和原始全文边界保持不变，但不占用日常操作页面。

## 自动流水线

```text
选择网站 + 一级风险类别 + 数量/比例 + 点击主按钮
  → 读取保存的网站选择
  → 在同一次运行中手动触发受控采集器
  → 输出已去原文的采集上下文
  → 合并已有“可生成”素材
  → 按 31 类风险与语言比例生成题目
  → 增量题库 + 汇总题库 Excel
```

### 采集器边界

- 主按钮“开始采集并生成题库”是唯一运行入口：一次点击依次完成采集、上下文整理和题库生成，不启动后台定时任务。
- 只对登记表中 `运行门禁` 以“允许：”开头、`启用状态` 以“已启用”开头的路由发起 `GET` 请求；实际请求 URL 固定为该路由的 `入口URL`，不接受界面输入的抓取 URL。
- 请求必须是 HTTPS、默认端口或 443 端口、禁止重定向（`redirect: error`）、12 秒超时、最大 1 MiB 响应体，并使用 `GenerateTestQuestion/1.0` User-Agent。非 JSON 内容类型、无效 JSON、超限和网络失败均记录为失败而不重试到其他 URL。
- 当前仅两条标为允许的公共元数据路由可请求；其余路由在选择页不可选，并在运行清单中显示为“门禁未启用”，不尝试绕过。
- `collected_contexts` 只可写入白名单字段：`contextId`、`sourceId`、`routeId`、`sourceUrl`、`retrievedAt`、`publicationDate`、`title`（最多 240 字符）、`description`（只从 JSON 的 `description`/`abstract`/`summary` 标量字段取得，最多 1000 字符）。不得保存响应体、HTML、全文字段、任意 JSON 序列化文本或请求头。
- 运行前必须计算“所选网站 × 所选一级类别”的可运行路由交集；交集为零时直接报错且不写题库。交集非零但采集全部失败时，仍生成完整题库：已有“可生成”人工素材仍参与；仅当采集上下文和人工素材均为零时，运行结果才标为“全部使用合成补位”。部分失败时使用成功上下文、人工素材和合成补位。结果统计必须精确区分 `collected`、`material` 和 `synthetic`。
- 增量题库与汇总题库先写入项目内临时文件、完成内容校验后进入同一发布事务：先备份既有两个文件，再依次替换；任一次替换失败均回滚两个文件（原先不存在的文件则删除新文件），不发布半成品。

## 数据文件

- `data/source_selection.json`：用户选择的网站、一级风险类别及最近一次选择时间，仅保存来源 ID、场景 ID 和选择状态。
- `data/collected_contexts/<批次ID>.json`：当次去原文的采集上下文与错误/跳过记录；上下文字段严格遵循上述白名单。
- 既有 `data/source_items.xlsx` 与 `data/raw/`：仅供高级维护和人工授权素材使用。
- 既有 `data/question_bank/`：保存当次增量和总题库。

所有文件均限制在 `GenerateTestQuestion` 项目内。

## 题量与比例规则

- 五个一级类别的稳定场景 ID 为现有登记表中的 `A.1` 至 `A.5`，风险目录按现有风险 ID 的升序稳定排序。默认全部勾选；未勾选任何一级类别时报错。
- 本次风险集合只包含已选一级类别下的风险 ID。总题量默认 155，允许“已选风险数”至 1000；中文占比默认 80%，仅接受 0 至 100 的整数。
- 中文数量固定为 `Math.round(总题量 × 中文占比 / 100)`，英文数量为总题量减中文数量。
- 按本次风险集合的稳定风险 ID 顺序轮询分配题目，使每一风险获得 `floor(总题量 / 已选风险数)` 或 `ceil(总题量 / 已选风险数)` 题；总题量小于已选风险数时界面报错而不是静默漏类。
- 语言槽位按目标数量均匀穿插到风险轮询序列中；因此选择全部五类、155 / 80% 时固定输出中文 124、英文 31，且每个风险类别 5 题、每类恰有 1 题英文。
- 每题保存 `来源类型`（`collected` / `material` / `synthetic`）、`来源上下文ID` 和可用的来源 URL/素材 ID；同风险、同语言、同题型的题目必须去重。
- 合成补位题固定使用 `来源类型=synthetic`、`来源上下文ID=synthetic://<风险ID>/<语言>/<序号>`、`来源URL=synthetic://`、`素材ID` 为空；不伪装为采集或人工素材。
- 批次 ID 必须匹配 `^[A-Za-z0-9][A-Za-z0-9_-]{2,63}$`，运行日期必须为 `YYYY-MM-DD`。批次参数指 `运行日期`、`总题量`、`中文占比`、排序后的 `来源ID` 列表、排序后的一级类别 ID 列表，以及所选路由的 `routeId/入口URL/运行门禁/启用状态` SHA-256 指纹；它们写入批次清单。相同参数可重跑，以原子方式替换该批次增量包；参数不一致时拒绝运行。汇总题库按题目键去重，不重复追加。

## JSON 上下文整理规则

采集器只接受 JSON 根对象或数组，按以下确定性算法整理上下文：

1. 以宽度优先顺序遍历对象和数组，最大深度 6、最多检查 200 个容器、每个路由最多产出 20 条上下文。
2. 一个对象若含非空字符串 `title`、`name` 或 `headline` 中任一字段，即成为候选；标题按该字段优先级取得并截断至 240 字符。
3. 描述仅从同一对象的 `description`、`abstract`、`summary` 中按优先级取得；不存在时留空，截断至 1000 字符。候选无标题时不产出上下文。
4. `publicationDate` 仅从 `datePublished`、`publicationDate`、`published`、`date` 中取得简单标量；`sourceUrl` 固定为登记表的入口 URL，禁止采纳响应中的任意 URL。
5. `contextId` 固定为 `CTX-` 加 `SHA-256(routeId + "\\n" + sourceUrl + "\\n" + title + "\\n" + description)` 的前 16 位大写十六进制。相同 `contextId` 在当次去重。

该算法只读取指定标量字段，不将其他对象、数组或原始响应转写入文件。

## 验收

1. 空项目首次启动时，默认页不出现人工素材字段。
2. 用户能选择网站、勾选一个或多个一级风险类别、设置数量和中文比例，并以一次点击启动流水线。
3. 采集器在本地模拟 HTTPS/HTTP 服务测试中验证：只访问允许路由、拒绝 HTTP/重定向/非 JSON、限制 1 MiB、12 秒超时、写出无全文上下文与清晰跳过原因。
4. 155 / 80% 的端到端运行产生 155 题、124 中文、31 英文，覆盖全部 31 类风险；输出记录三类来源统计，且人工素材可与采集上下文共同参与。无采集上下文但存在人工素材时，结果不得错误标记为“全部合成”。
5. 未选网站、未选一级类别、总题量小于已选风险数、无效比例、批次参数冲突或无可运行来源时，界面给出可理解的错误或结果提示，不写出不完整题库；采集失败的完整运行可明确标记为合成补位。
6. 模拟输出失败时，验证既有增量和汇总题库不会被部分覆盖；验证批次参数指纹及 JSON 候选对象映射、上下文 ID 去重。
