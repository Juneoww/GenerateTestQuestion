# OWASP 模型生成提示词替换设计

**状态：** 用户已确认，待进入实施计划
**日期：** 2026-09-28
**目标：** 将 v3.0.0 OWASP 的离线固定蓝图替换为真实大模型生成，同时复用 TC260 的模型调用、重试、调用留痕、批次目录和打开产物体验；最终 JSON 与 Excel 仍只交付六字段提示词记录。

## 1. 已确认边界

风险目录以 [OWASP 官方 2026 版资源及 PDF](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) 为准，不能沿用官网旧索引页仍展示的 2025 顺序。2026 排序为 LLM01 Prompt Injection、LLM02 Sensitive Information Disclosure、LLM03 Excessive Agency、LLM04 Supply Chain、LLM05 Data and Model Poisoning、LLM06 Unbounded Consumption、LLM07 Misinformation、LLM08 Hidden Context Exposure、LLM09 Vector and Embedding Weaknesses、LLM10 Improper Output Handling。风险中文名称是独立显示字段，不改变六字段输出中的编号／名称解耦校验。

- 使用“设置”页已有的 OpenAI 兼容 `baseUrl`、`apiKey`、`model`、`temperature`、超时和重试配置；生成模型只创作测试 prompt，不自动向被测模型发送任何内容。
- OWASP 不爬网站、不读取 TC260 网页素材，也不调用 TC260 的题目生成函数。
- 最终 JSON 每项只有 `riskId`、`riskName`、`userA`、`userB`、`prompt`、`assertion`；Excel 只有一张六列表，不能改用 TC260 的 13 列题库结构。
- 普通记录的 `userA == userB == ""`；跨会话记录的 `prompt == userB` 精确相等，测试人员只发送 B 内容一次。
- 复用 TC260 的批次目录、`llm_calls.jsonl`、`run.log`、`manifest.json`、输出路径设置和“打开批次目录 / 打开 Excel”交互。OWASP 保留独立 `OWASP-…` 批次前缀和更严格的成对产物发布，避免单独暴露 JSON 或 Excel 半成品。

## 2. 目标流程

```text
选择风险、数量、语言，并确认隔离测试环境
  → 程序按选中风险稳定分配待生成条数
  → 为每个风险构造可变系统提示词
  → 通过现有 OpenAI 兼容聊天接口请求模型
  → 解析六字段 JSON，做结构、会话规则、身份、语言和重复校验
  → 仅对不合格或不足的风险项补充重试
  → 写 JSON、Excel、llm_calls.jsonl、run.log 和 manifest
```

程序控制数量、风险归属、字段契约、重试上限和导出；大模型控制每条可复制 prompt 与断言的自然语言表达。这样不会回到固定模板复制，也不会让模型决定批次结构。

### 风险分配与最终顺序

输入风险 ID 先去重，再按当前 OWASP 目录的固定顺序排列；未知 ID 拒绝。`total` 必须不少于去重后的风险数，保证每个已选风险至少一条。设已选风险数为 `R`，则每项先得到 `total // R` 条，目录顺序最靠前的 `total % R` 项各再得到一条。模型调用也按此顺序进行；接受结果后按风险目录顺序轮转交错写入最终数组，直到每个风险的分配数量耗尽。因此混合批次、余数归属与最终行顺序都可预测、可测试。

## 3. 可变系统提示词

新增一个由程序构造的 OWASP 系统提示词函数。每次调用均注入：

- 本次固定的 `riskId` 与 `riskName`；
- 该风险的可操作测试目标，而不只是类别名称；目标只约束生成方向，不提供可直接复制的固定成品 prompt；
- 中文、英文或中英混合输出要求；
- 此风险本轮仍需生成的数量；
- 交互模式：单 prompt 或跨会话；
- 已接受的同批内容的有界近期摘要，要求不得复用相同文本或相同业务情境；完整批次仍由程序执行去重；
- 仅使用虚构、隔离测试数据，且每条必须是可直接复制给被测模型的完整输入；
- 只返回 JSON 数组，数组元素严格是最终六字段，禁止 Markdown、解释和额外字段。

`LLM02` 当前风险配置为跨会话模式；其系统提示词要求模型生成两段不同会话的真实输入，并让 `prompt` 与 `userB` 字节级相同。其他当前风险默认单 prompt 模式。该模式是生成配置，不是通用导出校验器中的“编号—名称绑定”；通用校验器仍接受未来独立的编号和名称。

特别是 LLM02，测试目标必须明确：User A 在一个会话中提供虚构且具体的秘密（如取件暗号），User B 在另一个会话中索取 User A 的秘密；秘密只能出现在 A，B 不能事先复述、暗示或包含该秘密，否则无法判定是否真的跨会话泄露。两段无关的日常对话也不是有效探针。其他风险也应有各自的目标说明，但不得变成十组固定成品提示词。

模型若返回与请求风险不符的 `riskId` 或 `riskName`，本轮候选被拒绝并重试，而不是由程序悄悄改写风险归属。

语言校验针对每段实际可复制的输入分别执行，而不能靠断言文本凑比例：中文输入的汉字占比不少于 20%；英文输入的汉字占比不高于 5% 且必须含拉丁字母；中英混合输入必须同时含汉字和拉丁字母。任意字段含“待填写”“示例提示词”等占位文本也会被拒绝。

## 4. 复用 TC260 的模型调用骨架

将 `question_generator.py` 中的 OpenAI 兼容聊天请求和 JSON 数组解析能力提升为可复用接口，保持 TC260 原行为不变。OWASP 生成器调用该公共接口，而不调用 `generate_questions()`：后者依赖网页 `item`、TC260 风险目录和 `{"question": ...}` 契约，不适合六字段提示词。

每次模型调用记录到 OWASP 批次自己的 `llm_calls.jsonl`，至少记录模型、风险、语言、请求数量、有效条数、尝试次数、提示词字符数和错误；不将系统提示词或模型调试字段写入最终 JSON / Excel。运行进度经现有队列机制写入 `run.log` 并反馈给 UI。

## 5. 校验、去重与重试

候选只有同时满足以下条件才被接受：

1. 精确六字段、全部为字符串，`riskId` / `riskName` / `prompt` / `assertion` 非空；
2. 与当前请求的风险身份相同；
3. 普通与跨会话字段满足既有 A/B / `prompt` 镜像规则；
4. 语言符合所选语言，prompt 与 assertion 为实际可复制文本而非“这里填写提示词”等占位语；
5. 与本批已接受记录不重复；所有记录的规范化 `prompt` 在整个批次全局唯一，跨会话记录还需按规范化 `(userA, userB)` 对去重。因此只改变 User A、却重复 User B 的候选也会被拒绝。
6. 跨会话候选若在 User B 中复用了 User A 的明显秘密标识（例如 4 位及以上数字取件码，或较长的含数字字母暗号），须拒绝并重试；这是可确定的防泄露下限，不声称能自动理解所有自然语言秘密。

每次请求的条数为 `min(仍缺数量, max(1, int(settings["maxQuestionsPerItem"])))`，沿用 TC260 的单次请求大小，并将历史设置中的零值安全钳制为 1。每个风险的正常请求轮数为 `ceil(该风险目标数 / 单次请求大小)`，额外最多允许 3 轮恢复请求；每一轮 HTTP、解析或“零个有效候选”失败时，至多按 `settings["retries"] + 1` 次尝试。于是单风险模型请求次数有明确上限：`(ceil(target / per_call_limit) + 3) × (retries + 1)`。若返回数量不足、解析失败或存在无效／重复项，后续调用只请求该风险缺少的数量，并把有界的近期已接受文本写入可变系统提示词的避免重复部分；完整批次的精确去重键一直保留在程序内，避免大批量生成时系统消息无限增长。模型响应异常也需写入调用日志并按同一上限重试；上限耗尽仍不足时批次标为失败，不用离线固定模板静默补齐。

## 6. 批次、导出与 UI

- `owasp_pipeline` 改为接收完整 `settings`，校验模型配置后运行模型生成器；不引入爬取阶段。
- 成功批次包含 `owasp_prompts.json`、`owasp_prompts.xlsx`、`manifest.json`、`run.log` 和 `llm_calls.jsonl`；最终 JSON 顶层保持六字段数组。
- 写入 JSON、Excel、成功 manifest 和日志时先使用隐藏暂存批次目录，完整成功后一次发布整个目录。模型调用或导出失败时，最终失败批次目录只发布失败 `manifest.json`、`run.log` 和 `llm_calls.jsonl`；不得发布 `owasp_prompts.json` 或 `owasp_prompts.xlsx`，也不得让 UI 保留上一成功批次的文件操作。
- Excel 导出仍为 `测试提示词` 单表和六个固定表头；界面结果表和双击复制行为不增加详情页或测试步骤。
- 模型生成的 Excel 单元格一律按字面字符串保存，即使内容以 `=` 开头也不能成为公式，以保证可复制原文及避免公式注入。
- OWASP 开始按钮与 TC260 一样检查模型配置；模型错误、JSON 格式错误和重试耗尽显示失败原因，旧批次的 JSON / Excel / 复制操作不得遗留为本次结果。
- 数量、语言或风险选择变化需即时刷新可生成状态；OWASP 的模型进度事件需在 OWASP 页面或全局状态栏可见，不能只写进 TC260 页日志。

## 7. 测试与验收

- 使用注入的假聊天函数，验证可变系统提示词包含本次风险、语言、数量、模式和避免重复内容，且不含网页素材。
- 覆盖模型返回正常单 prompt、正常跨会话、字段错误、身份错误、重复、JSON 解析失败、网络错误、重试成功和重试耗尽。
- 覆盖混合风险批次、`LLM02` 的严格镜像、最终 JSON / Excel 六字段、`llm_calls.jsonl` / `run.log` / `manifest.json` 落盘，以及 OWASP 不调用 crawler / TC260 `generate_questions()`。
- 回归验证 TC260 全套测试；它仍使用原有网页素材系统提示词和 13 列题库导出。

## 8. 非目标

- 不接入网站爬取或网页内容作为 OWASP 生成上下文。
- 不自动执行或发送任何生成的 prompt 到被测系统。
- 不增加富测试用例、步骤、条件、会话 ID、详情面板、第二张 Excel 表或模型元数据列。
- 不把模型无法满足数量时的固定蓝图当作成功结果。
