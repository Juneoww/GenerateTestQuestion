# GenerateTestQuestion 桌面端设计

## 目标

将现有的来源登记、素材归档和后续题库生成能力放进一个独立、手动启动的 Windows 桌面应用。应用不启动后台服务、不读取项目目录以外的文件，也不调用既有内容安全项目。

## 技术决策

- **界面**：Python 标准库 Tkinter/ttk，Windows 自带可运行，不引入 Electron、浏览器或额外安装步骤。
- **数据服务**：Node.js + 现有 `@oai/artifact-tool` 负责读写 Excel；Python 仅负责界面和启动本地命令。这样不会让两个运行时分别改写同一工作簿。
- **数据边界**：所有临时 JSON、原始材料、题库 Excel 和日志都在 `GenerateTestQuestion/data/` 内；应用只允许打开该目录下的文件或文件夹。

## 用户工作区

1. **概览**：展示来源路由、可生成素材、题库记录和最近输出位置，并提供刷新与打开项目数据目录。
2. **来源配置**：表格展示 `source_registry.xlsx / 来源路由`，按状态筛选并允许在受控项目内打开来源登记表维护。
3. **素材入库与提取**：从来源路由和风险目录下拉选择，粘贴正文或引用 `data/manual_import/` 内文件，提交后调用现有入库器；档案列表支持填写去标识化生成素材、事实要点、风险触发点、建议题型，并将素材设为“可生成”。
4. **题库生成**：人工输入批次 ID 和运行日期，点击生成首个 155 题全覆盖包。生成器仅读取“可生成”素材；不足风险用明确标记的 `synthetic://` 场景补位，保证 31 类风险每类 4 道中文题、1 道英文题。
5. **结果**：显示当日增量包和汇总题库路径，允许仅在应用内打开项目结果目录。

## 数据流

```text
桌面表单
  → desktop_data_service.mjs
  → source_items.xlsx / data/raw
  → 可生成素材
  → question_bank_service.mjs
  → data/question_bank/<批次>/题库增量.xlsx
  → data/question_bank/题库汇总.xlsx
```

原始全文不进入题库导出。题库记录保留风险 ID、场景、类别、题目语言、题型、来源信息、批次与题目文本；合成补位的来源明确标为 `synthetic://`。

## 容错与验证

- Python 通过临时项目内 JSON 文件向 Node 服务传递表单数据，服务结束后删除该文件。
- 一次入库失败不清空表单正文；Node 复用既有原始 JSON 恢复机制。
- 题库生成前检查 31 个风险目录；写入失败不更新汇总题库。
- 自动化测试验证 155 题、124/31 中英文比例、31 风险全覆盖、去重、Excel 输出和 Python 启动烟测。
- 界面启动仅由用户手动执行 `python app.py`。

## 本阶段取舍

首版不添加网页抓取器或定时任务。来源站点依然以登记表和授权门禁为准；桌面端负责让已允许的人工素材流程和题库生成可以完整操作。
