# 生成页固定区块高度与滚轮联动设计

## 目标

当“生成”页内容超出窗口高度时，用户可用鼠标滚轮从运行日志区域继续向下查看“原文 ↔ 题目对照”。
按用户后续补充，第 4/5 块应保持合适的固定阅读高度，由整页滚动查看，避免相互挤压后必须拖动分隔条。

## 布局规则

- 移除第 4/5 块之间的纵向 `PanedWindow`，两块在生成页中按内容高度依次排列。
- 日志区保留 8 行文本高度；对照区主体保留 360 像素高度，左右分隔条仍可调整列宽。
- 对照区左右两列默认按 2:3 分配阅读宽度，避免长题干摘要列把右侧详情挤出小窗口。
- 外层 Canvas 以内容请求高度计算滚动范围；缩小窗口不会压缩日志或对照区。

## 交互规则

1. 鼠标位于普通页面控件上时，滚轮滚动整个生成页。
2. 仅处理无 Shift 修饰的垂直滚轮事件。Windows/macOS 的 `<MouseWheel>` 以 delta 正负归一化为单步向上／向下；X11 的 `<Button-4>`/`<Button-5>` 分别映射为向上／向下。零 delta 或未知滚轮事件保持控件原有行为。
3. 从事件目标向上查找最近一个自带纵向视图的控件（本页实际使用的日志/详情 `Text` 与题目 `Treeview`）。该控件在本次方向还能移动时，优先保持其原有滚动；普通控件与不具备纵向视图的祖先直接交给生成页。
4. 当最近的内层控件已在本次方向的边界、无法继续移动时，同一次滚轮事件改为滚动整个生成页；向下到底和向上到顶均适用。内层与页面均到边界时，不额外消费事件。
5. 页面本身已完全可见时，不拦截控件原有的滚动行为，也不改变 Spinbox 等非滚动控件的默认滚轮语义。

## 实现边界与测试入口

- 调整 `app.py` 中生成页第 4/5 块布局及滚轮事件路由，不改变题目数据或其他工作区。
- 新增 `tests/test_app_scrolling.py`，使用透明但保持映射的真实 Tk 窗口检查几何及原生事件路径；不新增依赖。
- 运行 `.venv/Scripts/python -m unittest discover -s tests -p test_app_scrolling.py -v` 验证布局和滚轮，再运行 `.venv/Scripts/python tests/_ui_logic_check.py` 及全量 `unittest discover`。
- 回归覆盖：Windows/macOS 与 X11 的方向归一化；普通控件触发整页滚动；`Text` 和 `Treeview` 未到边界时的本地滚动；两类控件在顶部/底部继续滚动时的整页接力；以及页面和内层均到边界时不发生额外移动。
- 另覆盖页面无纵向溢出时，`Text` 与 `Spinbox` 的滚轮事件不会移动页面；`Text` 保持本地滚动语义，`Spinbox` 保持其默认数值语义。

## 验收标准

- 在 `1280×900` 窗口下，页面存在纵向溢出时，从运行日志底部继续向下滚动会使 `_page_canvas.yview()` 的首位置增加，并让“5. 原文 ↔ 题目对照”进入可视区域；从详情顶部继续向上滚动则使该首位置减少。
- 在 `1020×720`、`1280×900`、`1920×1080` 窗口尺寸之间切换，第 4/5 块的阅读高度保持不变。
- 滚到页面底部后，题目表、详情框与底部操作按钮完整进入可视区域。
- 题目详情中的长原文仍能在详情框内独立滚动。
- 既有 UI 逻辑检查与全量测试保持通过。
