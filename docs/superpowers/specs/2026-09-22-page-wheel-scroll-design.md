# 生成页滚轮联动设计

## 目标

当“生成”页内容超出窗口高度时，用户可用鼠标滚轮从运行日志区域继续向下查看“原文 ↔ 题目对照”。

## 交互规则

1. 鼠标位于普通页面控件上时，滚轮滚动整个生成页。
2. 仅处理无 Shift 修饰的垂直滚轮事件；Shift 或零 delta 的事件保持控件原有行为。滚轮方向以 delta 的正负归一化为单步向上／向下，避免依赖固定的 delta 数值。
3. 从事件目标向上查找最近一个自带纵向视图的控件（当前包括日志/详情 `Text`、题目 `Treeview` 和 `Listbox`）。该控件在本次方向还能移动时，优先保持其原有滚动；普通控件与不具备纵向视图的祖先直接交给生成页。
4. 当最近的内层控件已在本次方向的边界、无法继续移动时，同一次滚轮事件改为滚动整个生成页；向下到底和向上到顶均适用。内层与页面均到边界时，不额外消费事件。
5. 页面本身已完全可见时，不拦截控件原有的滚动行为，也不改变 Spinbox 等非滚动控件的默认滚轮语义。

## 实现边界与测试入口

- 仅调整 `app.py` 中生成页的滚轮事件路由；不改变题目数据、布局层级或其他工作区。
- 修改 `tests/_ui_logic_check.py`，用离屏 Tkinter 回归检查生成页的滚动状态；不新增依赖。
- 运行 `python tests\\_ui_logic_check.py` 验证 UI 事件路径，再运行 `python -m unittest discover -s tests -v` 覆盖既有自动化测试。
- 回归覆盖：普通控件触发整页滚动、内嵌文本控件未到边界时的本地滚动、文本控件在顶部/底部继续滚动时的整页接力，以及页面和内层均到边界时不发生额外移动。

## 验收标准

- 在 `1280×900` 窗口下，页面存在纵向溢出时，从运行日志底部继续向下滚动会使 `_page_canvas.yview()` 的首位置增加，并让“5. 原文 ↔ 题目对照”进入可视区域；从详情顶部继续向上滚动则使该首位置减少。
- 题目详情中的长原文仍能在详情框内独立滚动。
- 既有 UI 逻辑检查与全量测试保持通过。
