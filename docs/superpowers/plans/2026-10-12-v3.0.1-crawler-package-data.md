# v3.0.1 爬虫资源打包修复实施计划

> **目标：**修复 v3.0.0 Windows 单文件程序启动 TC260 爬取时缺失 `apify_fingerprint_datapoints` 数据文件的问题，并发布 v3.0.1。设计见 `docs/superpowers/specs/2026-10-12-v3.0.1-crawler-package-data-design.md`。

## 任务 1：让烟测覆盖运行时数据文件

**文件：** `tests/test_app_smoke.py`、`app.py`

1. 在 `tests/test_app_smoke.py` 增加一个缺失资源用例，只替换一个数据路径，断言 `app.smoke_test()` 抛出包含文件名的 `FileNotFoundError`。正常资源用例继续通过。
2. 运行该用例，确认旧实现失败，且失败原因是没有检测资源。
3. 在 `app.smoke_test()` 中检查依赖包公开路径函数对应的五个文件；缺失时抛出具体异常，不启动浏览器或网络请求。
4. 重跑定向测试和源码 `app.py --smoke-test`。

## 任务 2：先证实旧打包规则仍会失败，再修复

**文件：** `GenerateTestQuestion.spec`

1. 用旧 spec 构建临时冻结程序，运行 `--smoke-test`，确认它因缺少依赖数据而非零退出。
2. 在 spec 中加入 `collect_data_files('apify_fingerprint_datapoints')`，不改原有 Scrapling 收集和 GUI 单文件设置。
3. 重新构建并运行冻结程序烟测；核对归档中五个文件确实存在。

## 任务 3：补丁版本与发布

**文件：** `storage.py`、`tests/test_app_smoke.py`、`CHANGELOG.md`、`README.md`、`task_plan.md`、`progress.md`、`findings.md`

1. 先把版本测试预期改为 3.0.1，观察失败，再更新应用版本常量和文档。
2. 运行全量测试、编译、源码烟测、`git diff --check`；**版本号更新后再最终重建 EXE**，仅使用这份最终产物进行冻结程序烟测、归档资源检查、Windows 文件版本检查、GUI 隐藏启动检查。
3. 对最终 EXE 计算 SHA-256，生成校验文件。提交并推送源代码到 `main`，创建 v3.0.1 标签和新 Release，上传这份 exe 与校验文件；不覆盖 v3.0.0。
4. 复核远端 tag、Release 资产、哈希与本地版本一致。只有上述证据通过才宣称修复已发布；真实爬取仍需用户环境验证。
