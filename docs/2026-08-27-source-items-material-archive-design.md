# 素材归档与人工导入设计

## 目标

建立项目内可重复使用的素材入库链路，使已获许可或已人工确认的网页全文能够被保留、追溯并转化为可直接用于出题的结构化“生成素材”。本阶段不抓取网页、不生成题目、不接入桌面界面。

## 双层数据边界

```text
人工粘贴 / 受限文件导入全文
  → 导入暂存
  → data/manual_import/（仅在尚未入库时暂存超长文件）
  → data/raw/<批次ID>/<素材ID>.json（原始层）
  → source_items.xlsx / 素材档案（素材层）
  → 后续题目生成器
```

- **原始层**：保存标题、来源链接、发布时间、全文、正文哈希及授权证据，只在项目内 `data/raw/` 保存；用于追溯和重新提取。
- **素材层**：保存去标识化的生成素材、事实要点、风险触发点、建议题型和可生成状态；它是题目生成器的直接输入。
- 题库及后续导出不保存原始全文，也不得将原文直接复述为题目。
- `data/manual_import/` 只允许在人工等待入库时短暂保存超长全文；原始 JSON 原子写入后，导入器必须先删除该旁车文件，再更新工作簿。若删除失败，则不更新工作簿、保留暂存行并报告错误，避免“成功入库后仍在旁车目录保留全文”。

## 工作簿

输出为 `data/source_items.xlsx`，含以下工作表：

1. **说明**：人工导入步骤、状态定义和数据边界。
2. **导入暂存**：唯一允许粘贴全文或引用项目内原文文件的入口。成功入库后清除暂存全文/文件路径，仅保留入库结果；后续桌面界面将复用该字段结构。
3. **素材档案**：出题器读取的正式素材表。初始入库状态为“待提取”，只有补齐生成素材并设为“可生成”的记录才可被后续生成器选择。
4. **风险目录**：稳定复用现有 5 个场景和 31 个风险 ID、类别。
5. **下拉选项**：状态、语言、素材类型和授权确认值。

## 导入暂存字段

`导入行ID、来源路由ID、来源ID、来源链接、标题、发布时间、来源地区、来源语言、素材类型、授权确认、授权证据ID、授权证据URL、授权URL前缀、授权范围、确认人、确认日期、有效期、风险ID、场景、类别、原始正文、原文文件路径、导入批次ID、导入日期、入库状态、入库结果`

全文仅临时存在于此暂存区和入库后的原始层。`授权确认` 必须是“V3来源”或“人工确认-已获授权”；V0/V1 来源不得因为页面可访问而入库。V3 入库必须引用一个状态为 V3 的 `来源路由ID`，且来源链接必须同时符合路由上的 **许可分发 URL 模式** 与 **许可字段范围**；不能用 V3 身份导入同一来源站的其他网页。当前 S12 尚未在登记表补录可复查的 JSON 分发 URL，因此导入器拒绝其全文入库，而不是把目录页误作 JSON 分发。人工确认入库必须保留范围明确的授权证据、授权 URL 前缀、确认人、确认日期和有效期；授权范围须明确包含“保留全文”和“生成去标识化场景”。

`原始正文` 与 `原文文件路径` 严格二选一：Excel 正文不得超过 32,767 个字符；超过上限的材料必须以 UTF-8 `.txt` 或 `.md` 文件放入项目内 `data/manual_import/` 后引用其项目内相对路径。导入器拒绝绝对路径、`..` 路径穿越、重解析点、非 UTF-8 文件、公式、外部链接或超长单元格，不进行静默截断。

## 素材档案字段

`素材ID、导入批次ID、来源路由ID、来源ID、爬取网站、来源链接、标题、发布时间、抓取日期、来源地区、来源语言、素材类型、正文哈希、授权证据ID、授权证据URL、授权URL前缀、授权范围、确认人、确认日期、有效期、风险ID、场景、类别、生成素材、事实要点、风险触发点、建议题型、可生成状态、提取状态、原始档案路径、备注`

`生成素材` 是 200—500 字的去标识化上下文，用于直接生成题目；不是只有一句标题摘要。`事实要点`、`风险触发点`与`建议题型`让题目生成器可控地选择表达方式。

## 入库规则

1. 必填：来源路由 ID、来源 ID、HTTPS 来源链接、标题、原始正文或原文文件路径、风险 ID、场景、类别、语言、授权确认、批次 ID。
2. 风险 ID、场景和类别必须精确匹配 `风险目录`。
3. 来源路由 ID 必须存在于 `source_registry.xlsx / 来源路由`，且来源 ID、风险 ID、场景、类别与入口 URL 精确匹配。来源登记表为每条 V3 路由保存 `许可分发URL模式` 与 `许可字段范围`；缺少其中任一项时，V3 全文入库一律拒绝。
4. `V3来源` 仅在对应路由核验等级为 V3、状态为“已启用-受限接口”、实际资源 URL 匹配许可分发 URL 模式且字段范围允许全文保留时有效；`人工确认-已获授权` 必须有有效的授权证据 ID/URL、授权 URL 前缀、明确包含“保留全文”和“生成去标识化场景”的授权范围、确认人、确认日期和有效期。
5. 规范化规则版本固定为 `URL-NORM-V1` 与 `TEXT-NORM-V1`：URL 必须为无用户名/密码的 HTTPS URL，主机名小写、移除片段和默认端口、空路径归为 `/`、查询参数按编码后的名称和值排序；正文以 UTF-8 读取，Unicode NFKC 归一、CRLF/CR 归为 LF、首尾空白裁剪，内部内容不折叠。正文哈希是规范化正文的 SHA-256；素材 ID 固定为 `MAT-` 加 `SHA-256(规范化URL + "\n" + 正文哈希)` 前 16 位的大写十六进制字符；相同键不得重复入库。
6. 原始 JSON 必须保存素材 ID、导入行 ID、标题、来源 URL、发布时间、规范化规则版本、正文哈希、授权证据和完整正文。先原子写入 JSON；若 Excel 更新失败，下一次按导入行 ID 与来源 URL 查找并复用同一原始 JSON、补写一条素材档案，不产生重复数据。
7. 对旁车正文，原始 JSON 成功写入后先物理删除 `data/manual_import/` 中的原文文件，后更新工作簿；直接粘贴正文则在 Excel 更新成功后清除。成功的素材档案绝不写入完整原文；任一校验失败时不写入素材档案，错误写回“入库结果”。
8. 运行只可人工手动启动，所有输出限制在 `GenerateTestQuestion` 内。

## 验收

- 模板含 5 个工作表，覆盖全部 31 个风险类别。
- 空模板可导入、筛选和校验；下拉字段不可自由混填。
- 入库工具能将一条合格、范围明确的暂存记录写入原始 JSON 和素材档案，并清除暂存全文。
- 无授权、超范围 URL、同域但未配置的 V3 URL、风险映射不一致、正文为空/双重来源/超长、公式文本、非法旁车路径或重复记录均被拒绝且不污染正式素材档案。
- 生成器未来只读取“可生成”的素材档案行，原文仅用于追溯和重提取。
