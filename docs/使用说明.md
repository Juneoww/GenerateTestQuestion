# GenerateTestQuestion 使用说明

面向内容安全测试的桌面工具：**爬取网站 → 生成题目**。工具从已核验的可爬站点抓取公开报道与通报，
调用 OpenAI 兼容大模型，生成参照 TC260-003 风险分类（5 大类 31 小类）的中英文测试提示集题目
（仅题干，不含选项与答案），每道题可追溯到依据的原文与来源网页。

```
选网站 → 选风险小类 → 选题目形式、设数量与语言比例 → 一键生成
   └─ 后台自动：逐站爬取 → 内容去重 → 按小类×语言分配配额 → 按题目形式由大模型出题 → 校验去重 → 导出 Excel/JSON
```

## 1. 安装与启动

### 方式一：Python 源码运行（推荐开发/日常使用）

运行要求：Windows + Python ≥ 3.10，依赖仅 `scrapling[fetchers]`（抓取）与 `openpyxl`（Excel 导出）。

在项目目录执行（需已安装 [uv](https://docs.astral.sh/uv/)）：

```bat
uv venv
uv pip install -p .venv/Scripts/python.exe -r requirements.txt
run.bat
```

`run.bat` 已做双击友好处理：自动切到脚本所在目录启动程序，虚拟环境缺失或程序报错时会停留窗口显示原因。

命令行直接启动：`.venv\Scripts\python app.py`。

### 方式二：免安装 exe（Windows）

不装 Python 也能用：到 [Releases](https://github.com/Juneoww/GenerateTestQuestion/releases) 下载
`GenerateTestQuestion.exe`（约 60 MB），放到任意**可写**目录（如桌面、D 盘某文件夹）双击运行。

- 首次运行会在 exe 旁边释放 `data\` 目录（内置 16 个来源站点与 TC260 风险目录）。
  刻意**不**释放 `settings.json`——API Key 必须由使用者自己填写。
- 升级：下载新版 exe 覆盖旧文件即可，`data\`（已保存的设置与历史批次）不受影响。
- SmartScreen 首次可能提示"未知发布者"，点「更多信息 → 仍要运行」。
- 自行打包：配好虚拟环境后运行 `build_exe.bat`（PyInstaller 单文件模式），产物在 `dist\`。

### 自检与测试

- 无界面自检：`.venv\Scripts\python app.py --smoke-test`（exe 同理 `GenerateTestQuestion.exe --smoke-test`），
  正常时输出一段 JSON。
- 单元测试（全部离线可跑，抓取与模型调用均为 mock）：`.venv\Scripts\python -m unittest discover -s tests`。

设置与风险目录，改动 JSON 文件后用它刷新界面）。

程序分三个工作区（顶部页签）：

| 页签 | 用途 |
|---|---|
| 生成 | 日常主页面：选网站 → 在「题目类型」中选 TC260 风险小类 → 选「题目形式」 → 出题 → 看结果 |
| 来源管理 | 站点清单的核验、停用、新增 |
| 设置 | 模型接口与运行参数配置 |

**快捷键**

| 快捷键 | 作用 |

**推荐节奏**：首次使用按 设置 → 来源管理 → 生成 的顺序配置一次；之后日常操作只集中在"生成"页。

## 3. 设置页：配置模型接口

模型配置面板各字段如下（均为 OpenAI 兼容接口约定；DeepSeek / 智谱 / 通义 / Kimi / OpenAI 等均可）：

| 字段 | 说明 | 默认值 | 示例 |
|---|---|---|---|
| 接口地址 | **必须填到 `/v1` 等版本号一级**，工具自动在其后拼 `/chat/completions` | 空 | `https://api.deepseek.com/v1` |
| API Key | 服务商提供的密钥，输入框自动打码 | 空 | `sk-…` |
| 模型名 | 服务商的模型标识 | 空 | `deepseek-chat` |
| 温度 | 采样温度，越高越发散 | `0.7` | |
| 接口超时（秒） | 单次模型调用的超时 | `60` | |
| 出题重试次数 | 单次调用失败（网络/格式）后的重试次数 | `2` | |
| 单条原文最多出题数 | 一次调用向模型请求的题量上限 | `5` | |
| 爬取请求间隔（毫秒） | 同一站内两次请求之间的礼貌延时 | `500` | |
| 爬取超时（秒） | 单个网页请求的超时 | `15` | |
| 产物存放路径 | 生成产物根目录；留空用程序目录 `data\output` | 空 | `D:\题库` |

操作：

- **保存设置**：写入 `data\settings.json`。产物路径支持「浏览…」选择；相对路径按程序目录解析；
  保存时目录不存在会自动创建；历史批次列表与跨批次去重索引都跟随该目录。
- **测试连接**：向接口发一条极小的消息（"请只回复两个字：正常"），成功会在按钮旁显示模型回复，
  失败显示具体错误（HTTP 状态码或连接失败原因）。

高级参数（不在界面，直接改 `data\settings.json` 即可）：`responseLimitMiB`（单个网页响应大小上限，
默认 2 MiB，超过即放弃该页）。

> 安全提示：API Key 以明文保存在本地 `data\settings.json`，该文件不入 git；请勿把 `data\` 目录分享给他人。

## 4. 来源管理页：核验与管理站点

### 表格与状态

表格列出全部来源站点，列含义：来源ID / 名称 / 语言（zh、en）/ 方式（html、json）/ 引擎
（fetcher、stealthy）/ 状态 / 最近核验时间 / 备注。

状态机：

```
待核验 (pending) ──核验──► 可爬 (ready)      ← 只有"可爬"才出现在生成页
      └────────核验──────► 核验失败 (failed)  ← 修改站点配置后可重新核验
任意状态 ←──停用/启用──► 已停用 (disabled)     ← 不参与核验与生成
```

### 按钮操作

| 按钮 | 作用 |
|---|---|
| 核验全部 | 对所有非停用站点逐个自动核验 |
| 核验选中 | 先在表格里选中若干行，只核验这些行 |
| 停用/启用 | 把选中站点在"已停用"与原状态间切换 |
| 新增站点 | 弹窗录入新来源（见下） |
| 打开网站名单 | 打开 `data\reports\网站名单.md`（首次核验后才生成） |

有任务（核验/生成）运行中时不能发起核验。

### 自动核验的四道关卡

每个站点依次通过才判"可爬"，任一关失败会在核验日志写明原因：

1. **HTTPS 门禁**：URL 必须是 `https://`（端口 443、不含用户名密码）。
2. **可达**：列表页请求返回 HTTP 状态码 1xx–3xx（0 或 ≥400 即失败）。
3. **结构**：能用配置的条目正则从列表页提取到至少 1 条链接（JSON 方式则要求定位到条目数组）。
4. **内容**：抽取到的详情页正文 ≥ 50 字（JSON 方式看整体文本长度）。

### 新增站点

点「新增站点」弹出录入窗，字段如下：

| 字段 | 必填 | 说明 |
|---|---|---|
| 来源ID | ✅ | 唯一标识（如 `my-site`），不可与现有重复 |
| 名称 | ✅ | 显示名 |
| 入口 URL（HTTPS） | ✅ | 站点入口，必须是 HTTPS |
| 列表 URL 模板 | 可空 | 含 `{num}` 占位符的翻页模板（如 `https://site/news/list_{num}.html`），留空则用入口 URL |
| 条目正则 | 建议 | 从列表页 HTML 提取详情链接的正则，**须含一个捕获组** |
| URL 前缀 | 可空 | 拼接详情链接用的前缀（相对链接补全） |
| 语言 | — | zh / en，决定题目语言分组与语言池 |
| 方式 | — | html（正则提取）/ json（接口返回） |
| 引擎 | — | fetcher（普通抓取）/ stealthy（指纹伪装，反爬站点用） |

保存后站点为"待核验"状态，点「核验选中」验证通过即可进入生成页。

每个站点还有三个抓取限额（默认：从第 1 页起、最多 1 页、单站最多 20 条），需调整时直接编辑
`data\sources.json` 中对应站点的 `startPage` / `maxPages` / `maxItems` 字段，然后在主界面点「刷新数据」。

## 5. 生成页：五步生成题目

### 第 1 步：选择网站

- 只列出核验状态为"**可爬**"的站点，按「中文站点 / 英文站点」两组折叠展示。
- 点组标题条（▶ 箭头、组名）展开/收起；点站点整行即可勾选/取消。
- 工具栏：「全选」「清空」「全选中文」「全选英文」；标题条与工具栏的徽章实时显示"已选 n/m"。
- 没有可爬站点时会提示去"来源管理"核验。

### 第 2 步：「题目类型」——选择风险小类（参照 TC260，大类→小类）

- 界面沿用「题目类型」标签，但这里选择的是 TC260 风险小类；它不同于第 3 步新增的「题目形式」控制。
- 5 个大类折叠卡片，点大类标题条展开小类；小类是多选芯片（chip），点整块勾选。
- 大类标题行左侧的**三态框**可整组勾选/清空；"—"表示该组部分选中；**收起状态同样可以整组操作**，
  徽章始终显示该组已选数。
- 工具栏：「全选」「清空」；徽章显示全部"已选 n/31"。

完整 31 小类清单见[附录](#10-附录tc260-风险目录5-大类-31-小类)。

### 第 3 步：本次生成

| 参数 | 规则 |
|---|---|
| 题目形式 | 「文本对话题」（测文本模型）或「图片生成题」（测文生图模型）；选择会记住。图片生成题的题干是可直接输入文生图模型的提示词 |
| 生成数量 | 默认 50；**下限 = 已选小类数**（保证每个小类至少 1 题的配额），上限 1000 |
| 中文占比 | 默认 80%；0–100 的整数，按"四舍五入取半递增"拆分中英文配额 |

两种题目形式都会依据所选 TC260 风险小类和来源原文的情境生成；题目形式只改变题干面向的模型模态。

「开始生成」按钮的可用性由选择实时驱动：未选站点、未选小类时按钮置灰，并在下方红字提示
**具体缺什么**（如"还差网站：请至少勾选 1 个网站"）；就绪时提示"将按 N 题、中文 M% 生成"。
生成期间题目形式、数量、占比输入框与开始按钮均禁用，防止并发批次。

### 第 4 步：运行日志

爬取与出题全过程实时滚动输出：每站爬取统计、每次模型调用进度（"某站 出题 N 道，剩 M"）、
警告（黄色）与错误（红色）。同一份日志以 JSON 行落盘到批次目录的 `run.log`。

### 第 5 步：原文 ↔ 题目对照

- 左侧题目列表：序号 / 小类 / 题干摘要。题干摘要列装的是**全文**，窗口不够宽时拖动下方横向滚动条看完整题干。
- 点任一题，右侧会显示「**【题型】**」：文本对话题或图片生成题；再显示该题的题干、风险类别、
  **依据原文**与来源链接。加载缺少 `questionType` 的旧批次时，按文本对话题显示。
- 生成完成（或加载历史批次）后，右侧按钮可用：
  - 「打开批次目录」：直达该批次的所有产物文件夹；
  - 「打开题库 Excel」：直接打开交付用工作簿；
  - 「打开来源网页」：用浏览器打开当前选中题目依据的原文页面。
- 「加载历史批次」（`Ctrl+L`）：列出产物目录下所有含 `questions.json` 的批次（新→旧），
  选择后把题目载入对照区回看。

页面内容超出一屏时，滚轮滚动整页；日志与对照区之间的分割条可拖动调整高度比例。

## 6. 一次生成在后台发生了什么

点「开始生成」后，后台线程按批次编排：文本对话题的批次目录名为 `BATCH-YYYYMMDD-HHMMSS`，
图片生成题为 `BATCH-YYYYMMDD-HHMMSS-IMG`。

1. **爬取**：逐站抓列表页（按 `startPage`/`maxPages` 翻页），用条目正则提取详情链接
   （**仅同域链接**，跨域一律丢弃），逐条抓详情页提取标题与正文（过滤"登录/版权声明"等样板行），
   逐条落盘 `crawl/<来源ID>/items.jsonl`。每个请求之间按设置的毫秒数礼貌延时。
   内容按 SHA-256 哈希去重，与**历史所有批次**共享索引（`data\output\.hash_index.json`），
   重复内容不会再次出题。
2. **配额分配**：按中文占比拆出中/英文配额，再在各已选小类间**轮转均分**（余数给前几个小类），
   保证每类至少 1 题、总数恰为目标值。
3. **出题**：对每个"语言 × 小类"组合，在对应语言的内容池里**轮转喂原文**——每条原文取前 2000 字
   作为素材，连同小类说明一起发给模型。文本对话题产出测试文本模型的题干；图片生成题产出可直接
   输入文生图模型的画面提示词；两者都要求贴合来源素材情境（无选项无答案）。
   模型返回后逐题校验：长度 5–300 字、语言匹配（中文题汉字占比 ≥ 20%，英文题基本不含汉字且含字母）、
   哈希不与历史重复；不合格的题直接丢弃，单条原文最多发起 4 次调用、每次失败按设置重试。
4. **熔断**：连续 5 次"出题空手而归"即熔断终止批次（状态记为 `aborted`），**已产出的题目照常导出**。
5. **导出**：写 `questions.json` 与 `questions.xlsx`（Excel 导出失败不影响 JSON），
   生成 `manifest.json` 汇总（爬取统计、每个小类的目标/实出数、缺口、耗时）与爬取报告。

**缺口（shortage）**：某"语言 × 小类"实出数低于目标时会记入缺口清单，典型原因是该语言的内容池
太小或原文与小类情境不搭。可通过多选几个站点（扩大内容池）、提高"单条原文最多出题数"、
调低数量或调整语言占比来缓解。

## 7. 产物文件详解

产物根目录：设置页「产物存放路径」（留空则 `data\output`）。每次生成一个批次子目录；文本批次
形如 `BATCH-20260907-153000`，图片生成题批次在相同时间格式后追加 `-IMG`：
`BATCH-20260907-153000-IMG`。

```
data\output\BATCH-20260907-153000\
├─ questions.xlsx        交付用题库工作簿（见下）
├─ questions.json        全量题目数据（含完整原文与 questionType，程序内回看用）
├─ manifest.json         批次汇总：参数（含 questionType）、状态、爬取统计、各小类目标/实出、缺口、耗时
├─ run.log               运行日志（JSON 行，与界面日志同源）
├─ llm_calls.jsonl       每次模型调用一行：模型、题目形式(questionType)、小类、语言、素材ID、请求数/实得数、状态、错误
├─ crawl_report.md       本次爬取报告（分站统计）
└─ crawl\<来源ID>\items.jsonl    该站抓到的每条原文（标题、正文、URL、抓取时间）
```

另有目录级文件：

| 路径 | 内容 |
|---|---|
| `data\output\.hash_index.json` | 跨批次内容去重索引（删除它 = 允许旧素材重新出题） |
| `data\reports\` | 网站名单与核验日志（每次核验后刷新） |
| `data\sources.json` | 来源清单（含核验状态） |
| `data\settings.json` | 模型配置（含 API Key，明文存本地，不入 git） |
| `data\risk_catalog.json` | TC260 风险目录 |
| `data\_legacy\` | 旧版语料/题库批次归档 |

**questions.xlsx** 单工作表「测试题库」，13 列：序号、题干、**题型**、语言、大类、小类ID、小类、来源站点、
来源URL、原文摘录（截断 500 字）、批次、生成时间、模型。其中「题型」插在「题干」之后，值为「文本」或
「图片」。首行冻结，题干与原文摘录自动换行。

**questions.json** 每题字段：`seq`（序号）、`question`（题干）、`language`、`sceneCode`/`scene`（大类）、
`riskId`/`category`（小类）、`sourceId`/`sourceName`/`sourceUrl`（来源）、`evidenceText`（依据原文全文）、
`questionType`（`text` 或 `image`）、`model`、`generatedAt`；文件头的批次参数也含 `questionType`，
`manifest.json` 的参数与 `llm_calls.jsonl` 的调用记录同样保留它。

**兼容与迁移**：旧批次未记录 `questionType` 时，程序按文本题处理，历史批次无需迁移。v2.0.0 在 Excel
「题干」后插入了「题型」列，依赖旧列序的外部脚本应改为按表头名称定位列，不能再使用固定列号。

## 8. 常见问题与故障排查

**「测试连接」失败**
最常见原因是接口地址没填到 `/v1` 这一级（例如只填了 `https://api.deepseek.com`）。报错信息会带上
HTTP 状态码或连接错误：401/403 多为 Key 无效，超时多为网络或地址错误。

若报 **HTTP 403 且正文为 `error code: 1010`**，是接口站点前面的 Cloudflare 防火墙把程序当机器人拦截了，
与 Key 无关。v1.0.2 起程序的请求已带浏览器 User-Agent，正常不会再出现；若仍被拦（个别站点还会校验
TLS 指纹），可换一个接口地址（该服务商的其他域名）或走代理试试。

**生成的题数比设定的少**
先看运行日志与 `manifest.json` 的 `shortage`：哪个小类、哪种语言缺多少一目了然。原因通常是该语言
内容池不足（选的站点太少或都是单一语言）、原文与小类情境不搭（模型判不合格丢弃）、或命中了历史
去重（素材重复）。对策：多选站点、调低数量或占比、调高「单条原文最多出题数」、换更多样的站点。

**日志出现"连续 5 次出题无产出，熔断终止批次"**
批次被熔断中止，但已出的题已正常导出。多为模型接口持续报错（看 `llm_calls.jsonl` 的 `error` 字段）
或模型输出长期不符合格式/语言校验。先「测试连接」，必要时调高重试次数或换个模型。

**核验总是失败**
对照[四道关卡](#自动核验的四道关卡)看核验日志里的 `reason`：URL 非 HTTPS、HTTP 4xx/5xx、
条目正则提取不到链接（正则没写对或站点改版）、正文不足 50 字。反爬严格的站点可把引擎换 `stealthy`。

**exe 双击没反应或报错**
确保放在可写目录（不要放 `C:\Program Files`）；首次运行要释放 `data\`，权限不足会失败。
SmartScreen 拦截时点「更多信息 → 仍要运行」。命令行跑 `GenerateTestQuestion.exe --smoke-test`
可看 JSON 自检输出。

**改了 sources.json / settings.json 不生效**
JSON 是启动时读入、操作后回写的；外部改动后回到主界面点右上角「刷新数据」。

**项目路径含中文导致爬取报证书错误？**
已内置处理：crawler 会自动把证书复制到 `%TEMP%` 并设置 `CURL_CA_BUNDLE`，无需人工干预。

**想清空去重记录、让旧素材重新出题**
删除产物目录下的 `.hash_index.json` 即可。

## 9. 合规须知

- 所有来源仅接受 HTTPS（443、无凭据）；抓取限同域、逐请求礼貌延时（默认 500 ms，可在设置调大）。
- 来源以公开的**辟谣/监管/司法/事实核查类**页面为主，仅提取标题与正文用于出题，不做整站镜像。
- 公开可浏览不等于已获授权，请自行评估对目标站点的抓取频率与合规性。
- 生成的题目用于内容安全测试（检验 AI 服务是否会输出风险内容），题干本身可能包含诱导性表述，
  请在受控环境中使用。
