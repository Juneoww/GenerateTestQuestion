# v4.1.0 文本题同步生成文字图片开发文档

状态：方案草案，供评审；本功能尚未实现，版本号以开发验收结果为准。

## 1. 需求与优化方向

在现有“文本对话题”流程上增加可选能力：对生成的每条文字题干，以白色背景或用户选择的本地图片为背景，生成一张设定尺寸的文字图片。Excel 题库在原有列之后增加最后一列“文字图片”，直接显示对应的图片缩略图；批次目录同时保留独立的 PNG 原图，供后续导入视觉模型使用。

这是一种输出增强，不新增第三种题目形式。用户可在文本题模式下勾选“同时生成文字图片”；不勾选时保持现有纯文本题库。原有“图片生成题（模型生图）”继续使用文生图模型和原有流程，不受该勾选项影响。

每张图片呈现对应的测试题原文，不添加答案、额外提示、水印或风险标签。文字排版换行可以改变视觉行数，但不得增删、替换、遮挡或截断原题内容；文字模型生成不足时，不把未生成的题目计作图片成功。

## 2. 方案比较与适用边界

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| 文本题增加可选文字图片 | 沿用题干、风险、来源和序号，输出原文及对应图片 | 本期采用；便于同一题进行文本与图像输入对照 |
| 独立第三种题目形式 | 单独选择和维护文字图片批次 | 保留为后续扩展方向，本期不新增 |
| 仅在 Excel 放图片 | 查看方便，但不便批量读取 | 不采用；同时保留批次内 PNG 原图 |

本功能属于“文字入图”本地渲染，图片生成本身不调用文生图服务；已有爬取和文字模型出题流程仍可能使用网络和产生费用。它为视觉模型提供测试输入，不自动运行被测模型，也不自动判断风险是否命中或测试是否通过。

本期面向新生成的文本批次；历史 Excel 导入补图、复杂模板编辑器和 OCR 自动评分不在本期范围。上述历史批次范围是本方案假设，并非对已有数据的删除或改写。

## 3. 文字图片设置

设置页保留现有“文字模型”“文生图模型”“通用设置”标签，新增“文字图片”标签，其配置只作用于文本题的文字图片，不改变模型生图的配置或尺寸。

- **背景图片**：默认留空表示白底；点击“浏览…”选择本地 PNG、JPEG 或 WebP，可预览文件名及图片，并提供“清除背景”恢复白底。这里的“上传”是本地选择，不向服务器传送背景图片。每批统一使用同一张背景。
- **生成尺寸**：通过不可编辑的下拉框选择预设尺寸，单位为像素，无须填写宽度或高度。默认选择 **1280×1280（方形）**。下拉框提供以下常用尺寸：

  | 方向 | 预设尺寸（宽×高，像素） |
  | --- | --- |
  | 方形 | 512×512、1024×1024、1280×1280 |
  | 横图 | 1024×768、1920×1080 |
  | 竖图 | 768×1024、1080×1920 |

  所选尺寸持久化供下次使用。旧设置没有尺寸时使用默认值；若已保存的值不是预设项，应提示用户重新选择，不能静默改成其他尺寸。
- 选择的原始文件只作为导入来源；点击“保存设置”前验证并将背景处理后保存为程序数据目录内受管理的 PNG 副本，按内容哈希命名并原子写入，设置中持久化该副本的相对路径、哈希与尺寸，供下次启动和后续批次使用。保存副本或设置失败时报告错误并保留原有已保存配置；不覆盖或删除用户原图，也不删除其他任务的数据。此后用户移动原始文件不影响设置。“同时生成文字图片”勾选状态仍不跨启动持久化。
- 背景原始绝对路径不写入结果或日志，背景图片不上传到模型。历史设置缺少新字段时默认白底及 1280×1280；新设置不影响其他标签。若受管理副本被删除、损坏或与保存的哈希不一致，勾选文字图片并开始时明确提示重新选择或清除背景，不得静默退回白底。取消选择文件时保留原设置；清除仅解除引用，不删除用户原图或用途不明的现有数据。

## 4. 使用流程

1. 按需在“设置 → 文字图片”选择本地背景、从下拉框选择图片尺寸并保存；未设置时使用白底 1280×1280。
2. 按原流程选择“文本对话题”、来源站点、风险分类、数量及中英文比例。
3. 可选勾选“同时生成文字图片”。仅在文本对话题模式显示或启用该选项；每次启动程序默认不勾选，同一次运行中切换模式时保留当前勾选状态，但仅对文本对话题生效，不影响模型生图。
4. 启动时冻结本次宽高与背景配置，在爬取和文字模型调用前校验受管理副本并建立批次背景快照；之后沿用现有爬取、配额、文本模型出题和题干去重。生成有效题干后，按稳定序号逐题在本地绘制文字图片；执行中修改设置只影响后续批次。
5. 生成成功的行在 Excel 最后一列显示缩略图，对应的完整 PNG 写入批次 images 文件夹。用户通过题目序号、JSON 相对路径或文件名找到原图。
6. 结果界面和批次汇总分别显示文本题数、图片成功数与图片失败数。渲染失败时保留题干和原因，Excel 对应图片列显示失败提示，不生成占位图片冒充成功。

使用文字图片时无需填写或验证文生图接口。现有文字模型、来源和风险等校验继续生效。沿用现有跨批次素材去重，不因勾选配图而自动清空索引或复用旧素材。

## 5. 图片设计与文字完整性

- 输出为一题一图的 PNG，画布使用设置的宽高，默认为 1280×1280、白底深色字，四周留白；图中文字仅包含完整题干。
- 使用 Pillow 按字体实际测量宽度，实现中文逐字、英文按词边界和已有换行的自动排版。记录的原始题干不因插入视觉换行而改变。
- 布局根据短边按比例缩放；1280×1280 时基准字号为 48 像素、基准最小字号 28 像素、安全边距 96 像素；最小字号至少为 20 像素，每个方向边距不小于 32 像素。按画布实际宽高测量并逐级缩放，保证所有行都在边距内，不能低于可读下限。参数作为有名常量，最终以实际视觉验收为准。
- 用户背景先按图像方向信息纠正；保持原宽高比完整缩放到画布内，多余区域以白色留边，不拉伸或裁切。题干绘制在居中的白色文字面板上，面板不透明度至少 95%、正文深色，在复杂背景上保持可读；面板仅覆盖必要文字区域且不遮挡题干。
- 预检用户背景可读取、实际解码、格式、文件大小和像素上限（建议原图不超过 20 MiB 且不超过 4000 万像素）；超限、损坏或不支持时明确失败。保存设置时先写入受管理副本；批次创建后、爬取和出题前再把副本写入批次的 background.png 并计算哈希，防止后续设置变化影响该批次。保存失败即终止批次，不能暗中改用其他背景或继续计费。每题使用同一快照；转码不复制 EXIF 定位等元数据，不覆盖原文件。白底时无需背景副本。
- 如果最小字号仍无法完整容纳文字，标记本题图片失败，保留题干和错误原因，不裁字、不添加省略号。标点、数字、中英文及换行的顺序必须保留。
- 明确中文字体来源、回退和字形覆盖检查。系统字体缺失或字符不能显示时应明确失败，不能将方框或替代字符计作成功。若随程序分发字体，须确认授权，并验证 Windows EXE 的字体资源可用。
- 图片状态反映文件输出结果，不代表内容安全判断；本地渲染不会产生图像服务的内容审核拒绝。

## 6. 导出与数据契约

### 6.1 批次文件

勾选文字图片后仍使用现有文本批次命名和原子创建机制，不覆盖已有批次：

    BATCH-YYYYMMDD-HHMMSS/
      images/
        0001.png
        0002.png
      background.png          # 仅选择背景图片时存在
      questions.xlsx
      questions.json
      manifest.json
      image_progress.json
      run.log
      llm_calls.jsonl
      crawl_report.md
      crawl/

图片文件名由批次内稳定序号生成，不以题干作文件名。先写临时文件、验证图片可解码和画布尺寸，再原子落盘；失败清理本次临时文件。图片相对路径以批次目录为基准，分享或移动时需保留整个批次目录。

### 6.2 Excel

- 未勾选时，文本题 Excel 保持现有 13 列、列名与顺序；不会插入空的图片列。
- 勾选时，保留前 13 列并在最后追加“文字图片”列。每条成功题目的最后一列展示该题图片的缩略图；失败题显示“生成失败”及简要原因，题干仍保留。
- Excel 中的图片是锚定在单元格位置的图片对象，不是单元格文本值；对应行需固定合适的行高和图片列宽，缩略图按比例缩放且不得覆盖相邻行或列。
- Excel 和 WPS 对图片随单元格排序、筛选、复制的行为可能不同；须在目标软件中实测，不承诺默认始终跟随。批次序号与 JSON 路径是原图关联依据，排序后如未验证图片跟随，应重新按序号核对，不能把缩略图位置作为唯一依据。
- 缩略图仅用于快速浏览。完整图片独立存储在批次 images 文件夹；真实题干和原图路径以 questions.json、序号及对应文件为准。不得仅依赖图片锚点推断对应关系。
- 大批次嵌入图片会增加工作簿体积；嵌入前生成适当尺寸的压缩缩略图并保持所选宽高比，按固定单元格边界等比缩放，独立 PNG 原图保持用户所选完整分辨率。具体缩略图大小及视觉布局需用 Excel 或 WPS 实测；横图和竖图不得拉伸或覆盖相邻行列。
- 文本题开启该选项时新增一列属于导出契约变化；外部脚本建议按表头读取。现有模型生图 Excel 的列和语义保持不变。

### 6.3 JSON 与汇总

文本题仍保持 questionType 为 text，原 question 保存完整题干。批次参数增加 textImageEnabled 布尔值；开启时每条题记录增加：

| 字段 | 含义 |
| --- | --- |
| textImageStatus | success 或 failed，仅描述本地图片输出 |
| textImagePath | 成功时为 images/0001.png 等相对路径，失败时为空 |
| textImageError | 失败原因；成功时为空 |
| textImageTextSha256 | 原题干 UTF-8 字节的 SHA-256，用于核对渲染输入 |
| textImageFontSize | 最终使用字号，失败时可为空 |

批次参数与 manifest 记录本次冻结的文字图片宽高、背景类型（白底/本地背景）、批次内 background.png 相对路径及 SHA-256（白底时路径与哈希为空），以及字体、布局所需参数；不得记录用户原始绝对路径或图片 EXIF。批次汇总分别记录有效题干数量、图片成功数和失败数；最终成功数加失败数等于已生成的有效题干数。已有的模型生图 imageStatus、imageModel、imageSummary 等字段保持原意，不把本地图伪装为图像模型生成。

旧批次缺少 textImageEnabled 和图片字段时按未开启处理，不回写历史文件。Excel、JSON 或图片导出出现部分失败时，界面和日志均应如实显示；不能因文本题成功就宣称所有图片生成成功。

## 8. 异常、测试与验收

- UI 与路由：不勾选时行为及 Excel 前后完全保持现状；勾选后每条有效文本题最多一张图片，不调用文生图接口；切换模型生图后原功能正常。
- 图片质量：中文、英文、中英混排、标点、长文本、原始换行和缺字场景均有明确预期；文字完整可读、不溢出、不被错误替换。不能仅凭 OCR 自动比对声称逐字正确，应人工抽样核对。
- 设置与背景：首次默认白底 1280×1280；本地 PNG/JPEG/WebP 的选择、预览、清除、保存重启后恢复和旧配置兼容；导入后删除或移动原图，已保存设置仍可用；受管理副本删除、篡改、不可读、损坏时提前提示且不调用模型；原图不被修改，受管理副本及批次 background.png 的相对路径与哈希一致；设置更改不影响进行中批次。
- 预设尺寸：逐一测试全部下拉选项，验证实际 PNG 宽高、原图等比完整呈现、文字面板可读不溢出、缩略图比例正确；下拉框不可输入自定义值，异常保存值须提示重新选择。长题在最小字号仍放不下时明确失败，不裁切。
- 文件关联：模拟三条文本题，其中两张成功、一张失败；检查每题序号、JSON 路径、独立 PNG、Excel 对应行缩略图和失败提示一致，图片成功数为二。
- Excel：读取实际工作簿检查图片对象数量、锚点和行列布局，并在 Excel 与 WPS 分别检查打开、排序、筛选后的对应关系与视觉效果，记录不一致的限制；把 Excel 单独移动时缩略图仍可显示，把整个批次移动时相对路径仍可定位原图。
- 错误处理：缺字体、字形不支持、文字超界、图片写入失败、Excel 嵌图失败均不得静默成功；图片失败保留题目，Excel 输出失败时保留可用 JSON 和图片。
- 兼容与回归：历史文本及图片批次可查看，原有文本题、模型生图及 OWASP 工作区测试通过；未提供图像模型配置也能开启文字图片。
- 版本与打包：运行源码和冻结程序自检；Windows EXE 真实打开样例，检查中文字体、图片解码、Excel 展示。测试使用替身和本地样例，不发起真实付费请求。
