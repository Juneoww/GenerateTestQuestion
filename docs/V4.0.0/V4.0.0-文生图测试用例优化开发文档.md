# v4.0.0 文生图测试用例优化开发文档

状态：按确认的设置页布局实施；功能以代码和验证结果为准。

## 1. 背景与目标

当前 TC260「图片生成题」使用聊天模型，根据来源素材和风险类别生成文字提示词；程序不会调用图像模型。现有 `questions.xlsx` 中“题型”为图片的记录，其题干仍是提示词。用户提供的 `BATCH-20261103-095641-IMG` 包含 40 条这样的记录，批次目录和工作簿均无图像文件。

本次目标：新建图片题批次时，在生成提示词后调用独立配置的文生图模型，逐条保存真实图片，并输出提示词、图片文件及关联信息，供后续图片内容安全测试使用。原提示词仍须保留，作为图片来源和复现依据。图片由模型生成并不意味着其实际包含指定风险，也不意味着模型通过或未通过安全测试；风险匹配需后续审核。

## 2. 范围与边界

- 仅处理更新后**新生成**的 TC260 图片题批次，不回填历史 Excel、JSON 或批次目录。
- 每条有效提示词默认请求生成 1 张图片；图片题批次必须配置图像模型，不能静默退化为仅文字题库。
- 保留现有聊天模型出题流程与文本题功能；不改变 OWASP LLM / Agentic 工作区。
- 最终图片作为独立文件交付，Excel 和 JSON 使用相对路径关联，不要求在 Excel 内嵌图片。
- 初期支持约定的 OpenAI 风格图片生成 HTTP 接口；不承诺兼容所有供应商的私有协议、异步任务接口或全部模型参数。
- 不建设历史批次补图、批后断点续传或单条手动重试界面。运行期间允许对瞬时错误作有上限的自动重试。
- 本文不预设新版号、发版、推送或覆盖本地 EXE；这些在实现与验收阶段另行决定。

## 3. 使用流程与界面

1. 设置页顶部采用三个标签：「文字模型」「文生图模型」「通用设置」。文字模型保存既有聊天接口配置；文生图模型单独配置接口地址、API Key、模型名、超时和重试次数；通用设置保留爬取参数、产物路径等现有配置。切换标签不丢失尚未保存的输入。图像接口地址填写到版本前缀，例如 `https://example.com/v1`，程序拼接 `/images/generations`。Key 使用密码样式显示，并遵循现有设置的本地保存方式。
2. 用户在 TC260 生成页选择「图片生成题」并配置来源、风险、数量及语言。开始前同时校验聊天模型和图像模型必填项；图像 Key 是否必填按部署环境处理，不在 UI 里强制所有兼容服务都有 Key。
3. 后台继续执行爬取、提示词生成、去重及配额流程。提示词获得稳定序号后，按序逐条调用图像服务，并在界面显示当前序号、成功／失败数量和阶段进度；调用不阻塞主界面。
4. 完成后打开批次目录即可获取图片，结果区与完成提示分别显示提示词数、图片成功数、拒绝数、失败数；可查看对应路径和失败原因。提示词生成成功不等于图片生成成功。

图片服务可能产生计费或拒绝请求；开始前界面应明确本批次最多按有效提示词数发起生图请求，重试可能增加请求数。无需实际调用图片模型即可完成常规自动化测试。

## 4. 设计方案

### 4.1 模块职责

| 文件 | 计划职责 |
| --- | --- |
| `storage.py` | 增加图像接口配置、默认值及类型校验；旧设置文件缺省时兼容读取。 |
| `app.py` | 增加图像配置项、启动前校验、生成进度与图片统计展示，沿用后台线程和事件队列。 |
| `question_generator.py` | 沿用当前提示词生成与校验逻辑；输出仍保留 `question`。 |
| `image_generator.py`（新增） | 负责图片请求、响应解析、错误分类、受控重试及字节验证；不负责题目配额。 |
| `pipeline.py` | 为图片题分配序号、调用图像模块、保存文件、记录每题状态并汇总；文本题路径保持原行为。 |
| `excel_export.py` | 图片题导出追加图片字段；文本题维持现有 13 列顺序。 |
| `requirements.txt`、`GenerateTestQuestion.spec` | 显式声明 Pillow 用于实际解码验证，并核对 PyInstaller 打包收录。 |
| `tests/`、`README.md`、`docs/使用说明.md` | 增加覆盖与用户使用说明。 |

### 4.2 图片接口适配

首版适配 `POST {imageBaseUrl}/images/generations`，以 JSON 发送 `model` 和 `prompt`；不无条件发送供应商或模型不一定支持的参数，默认接受一张图片。成功响应从 `data[0]` 读取 `b64_json` 或 `url`；响应既无可用字节也无可下载 URL 时记为失败。不同服务未实现该契约时须明确提示不兼容，而不是声称“所有 OpenAI 兼容接口均可用”。

接口参考：[OpenAI 图片生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)、[图片生成指南](https://developers.openai.com/api/docs/guides/image-generation)。例如 GPT Image 不支持 `response_format`，实现时不得无条件发送该参数；URL 返回与各服务的参数支持仍须逐个核实。

对于 URL 响应，及时下载并保存实际图片；仅保留链接不算成功。下载不携带图片服务的 Authorization，限制协议、重定向、超时及字节上限；解码后验证受支持图片类型，以实际文件类型确定扩展名。网络响应、HTML 错误页、空文件或损坏图片不得计为成功。详细协议及模型支持范围以接入服务的官方文档为准。

图片完整性使用 Pillow 实际解码验证，不能只依据文件扩展名或文件头；测试需覆盖截断或损坏图片。新增直接依赖并在后续打包时验证该依赖可用。

单次请求响应的图片按安全、固定名称保存，不使用提示词或远程 URL 作为文件名。先写临时文件并验证，再原子替换为目标文件；失败清理本次临时文件，避免残缺文件被识别为成功。API Key、认证头、图片 base64 和带签名的下载 URL 不写入运行日志、JSON、Excel 或错误信息。

### 4.3 批次流程与计数

1. 校验参数和模型配置，创建批次并按现有逻辑爬取与生成提示词。
2. 为最终提示词分配批次内连续的 `seq`；同一批次内序号即关联键。每题 1 次图片生成任务，文件名例如 `images/0001.png`。
3. 顺序生成并落盘，记录结果及脱敏错误；个别题失败或拒绝时继续处理其余题。限流、超时、临时服务故障按设置进行有界重试；超时可能已经产生费用，应在使用说明中说明；鉴权失败、参数错误、明确拒绝不盲目重试。对明确影响整批的鉴权或配置错误，停止后续生图请求，将未处理题目记为 `failed` 并注明未调用的原因，保留已有结果。
4. 生成结束后导出 JSON、Excel、manifest 和日志。图片失败不删除已成功图片及提示词。若提示词阶段熔断，沿用现有中止语义，已生成的提示词仍进入图片阶段并如实汇总。
5. 保留现有批次 `status` 对爬取／提示词阶段的语义，不把图片阶段部分失败隐藏为完整成功：新增独立 `imageSummary.status`（`completed`、`partial`、`failed`、`not_started`），界面和导出同时展示两个状态。无有效提示词时为 `not_started`。

生图阶段开始前先原子写入 `image_progress.json` 快照，记录批次未完成和所有题目；快照内尚未处理的题目使用 `pending`，当前请求可使用 `in_progress`，已处理题目使用下文规定的三个终态。每次图片文件落盘或记录失败后更新快照。正常结束再生成最终导出，最终题目不得保留 `pending`／`in_progress`；快照也可保留供追溯。异常退出后，已保存图片及最近快照可人工追溯；本期不承诺自动恢复，且快照更新前发生中断时仍可能需要人工核对已落盘文件。

批次计数分开维护：`promptCount` 为有效提示词数；`imageSuccessCount`、`imageRejectedCount`、`imageFailedCount` 分别对应真实图片已保存、明确拒绝及其他失败，其和等于已处理提示词数。期望数量与提示词不足仍使用现有 `shortage`，不得用提示词数冒充图片成功数。

最终状态的计算规则：没有有效提示词为 `not_started`；有提示词且全部图片成功为 `completed`；至少一张成功且至少一条拒绝或失败为 `partial`；有提示词但成功数为零则为 `failed`。正常结束时成功数、拒绝数和失败数之和必须等于 `promptCount`；中间快照允许存在待处理数。

### 4.4 输出结构

```text
BATCH-YYYYMMDD-HHMMSS-IMG/
  images/
    0001.png
    0002.webp
  questions.xlsx
  questions.json
  manifest.json
  image_progress.json
  run.log
  llm_calls.jsonl
  crawl_report.md
  crawl/
```

扩展名按图片真实格式确定；没有图片的题目不创建占位图片。相对路径相对于批次目录／同目录下的 `questions.xlsx`，例如 `images/0001.png`。移动或分享时需保留整个批次目录及其内部结构。

### 4.5 数据契约

在新图片批次的每个 question 记录中保留既有字段，追加：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `imageStatus` | 字符串 | `success`、`rejected`、`failed`；只有真实文件成功保存才是 `success`。 |
| `imagePath` | 字符串 | 相对路径；拒绝或失败时为空字符串。 |
| `imageModel` | 字符串 | 图片生成模型名，与现有提示词生成 `model` 区分。 |
| `imageError` | 字符串 | 脱敏后的简要原因；成功时为空字符串。 |

`manifest.json` 和运行汇总追加 `imageSummary`，至少包含上述阶段状态、提示词数、图片成功数、拒绝数和失败数。日志按序号、模型名、状态、尝试次数和耗时记录；不得存凭据、图片内容或临时下载地址。对无法可靠识别为拒绝的错误归为 `failed`，不要根据模糊文字推断拒绝。

图片题 Excel 在现有 13 列之后追加「图片路径」「图片状态」「图片模型」「图片失败原因」；“题干”仍保存原提示词，“模型”仍是提示词生成模型。路径可提供相对链接，但单元格必须保留可直接读取的相对路径。文本题 Excel 维持原 13 列与顺序，历史 JSON 和 Excel 保持可读，缺失新字段不影响历史结果展示。

注意：图片题新增列属于导出契约变化；使用固定列数的外部脚本需更新，建议根据表头读取。图片状态与风险判定分离，不自动为生成图打风险结论。

## 5. 错误和异常处理

| 情况 | 行为 |
| --- | --- |
| 生图配置缺少地址或模型 | 在调用爬虫和模型前提示并终止启动。 |
| 返回成功但没有有效图片 | 本题标记 `failed`，记录简要原因，继续处理后续题。 |
| 内容策略明确拒绝 | 标记 `rejected`，不无限重试，不生成虚假文件。 |
| 限流、超时、临时网络故障 | 按配置有界重试；耗尽后标记 `failed`。 |
| 鉴权或参数错误 | 本题记录错误并给出可操作提示；不按瞬时故障盲目重试。 |
| 磁盘写入或图片校验失败 | 本题标记 `failed`，清理本次临时文件，保留已成功文件。 |
| 程序异常退出 | 不宣称批次完成；本期不承诺批后恢复或自动续跑。 |
| Excel 导出失败 | 沿用现有策略保留 JSON 和图片，并在运行结果报告导出失败。 |

## 7. 验证与验收

自动化测试使用模拟服务或注入替身，不调用真实付费 API：

1. **配置与 UI**：旧设置读取正常；图片题缺少图像配置时不开始运行；文本题无需图像配置；生成线程和进度事件不阻塞界面。
2. **接口**：验证请求地址、模型、提示词及单图返回；覆盖 base64、URL 下载、无效响应、非法图片、超限、超时、限流、鉴权错误、明确拒绝和重试上限；日志与导出不含 Key、base64 或签名 URL。
3. **端到端批次**：构造至少 3 条提示词，分别模拟成功、拒绝和失败；核对序号、真实文件、相对路径、状态和汇总数量一致；无成功文件时不伪造图片；熔断后已有题目的处理可追踪。
4. **兼容性**：文本题不调用图片接口、原有 Excel 13 列不变；旧图片批次能正常读取；OWASP 功能及现有测试通过。
5. **人工验收**：配置一个实际支持该契约的图像模型，生成少量新图片题，在文件管理器和 Excel 中核对每条成功记录的图片可打开、提示词及相对路径对应、失败状态可辨识；检查图片是否适合后续人工安全测试，但不以生成成功推断风险命中。移动整个批次文件夹后再次验证相对路径。

建议回归命令（以仓库根目录 PowerShell 执行）：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe app.py --smoke-test
git diff --check
```

真实服务的凭据、模型支持、收费和内容限制由实际使用者确认；未配置可用服务时只能完成模拟验证，不能宣称真实生图验收通过。
