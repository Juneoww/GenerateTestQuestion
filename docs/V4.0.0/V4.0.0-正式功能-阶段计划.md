# V4.0.0 正式功能阶段计划

日期：2026-10-19。P0–P3 已完成；P4 的真实模型抽样、本地 EXE 构建与验证完成，远端发布尚未进行。开发分支为 `codex/v4-agentic-top10`。本文件保留阶段划分，实际执行见[正式实施计划](./V4.0.0-正式功能-实施计划.md)和[验收记录](./V4.0.0-正式功能-验收记录.md)。

## P0 原型与交互验收（本轮）

完成独立五页 Tkinter 原型，重点验证 Agentic 风险选择、六字段结果、环境说明、LLM 页隔离和预览。演示使用固定虚构数据，具体任务见[原型实施计划](./V4.0.0-原生原型-实施计划.md)。

## P1 版本化目录与共享生成引擎

将风险目录、框架标识和策略从 `owasp_prompt_generator.py` 分离到专用配置模块，保留旧调用默认采用 LLM 目录。新增 ASI01–ASI10 的官方英文名、项目中文名、生成目标、注入位置和环境要求。

生成引擎继续复用 `question_generator.chat_completion`、JSON 解析、配额、语言校验、全批去重、有界历史和有限补生成。LLM02 的秘密泄露检查独立为 LLM 策略，Agentic 不能直接继承该规则。不得使用原型固定文本补足正式模型失败的条数。

验证：框架与风险编号不匹配在调用模型前拒绝；两套目录的配额和语言行为一致；LLM02 回归；ASI 每类的系统消息包含明确测试目标与环境约束。

## P2 正式批次和环境信息发布

扩展 `owasp_pipeline.py`，保持现有 LLM `OWASP-` 前缀，Agentic 使用独立 `AGENTIC-` 前缀。manifest、调用日志和完成事件均带框架与目录版本；记录格式版本独立于应用版本。

环境文件逐行关联最终记录，必须描述与该条 prompt 一致的环境和输入位置。正式实现前落实生成来源：优先由程序为每条候选分配已知环境配置，再约束模型在该配置中生成，避免模型使用未声明的工具；如允许模型自创环境，则内部响应必须携带并校验环境元数据，导出前再投影为六字段。两种方式须在 P1/P2 详细计划中明确选择，不能仅从风险名称推测任意模型文本的环境。

JSON、Excel、环境文件、manifest 与日志一并通过隐藏暂存目录发布。任何文件失败不发布半成品，UI 撤下本次旧结果操作。

验证：逐行关联、补生成与重排行号一致；环境文件失败回滚；路径切换、同秒批次和 Windows 文件锁行为保留回归。

## P3 正式桌面页接入

将独立 Agentic 页接入 `app.py`；共用页面控件构建能力，各页独立状态。通过事件中的框架标识定位正确页面，避免全局状态和历史路径串批。保留单批次串行执行。

增加打开环境说明入口，同步五页快捷键、设置页路径说明、烟测与使用文档。回归 TC260、旧 LLM 和爬虫依赖资源。

## P4 真实抽样、打包与发布

在用户已配置的生成模型上抽样验证十类 ASI 的输出、去重和环境一致性；候选提示词由人工在匹配能力的隔离目标环境验证。源码单测通过不代替模型联调或实际 Agent 验证。

正式升级应用版本为 4.0.0，更新 CHANGELOG 和使用说明；验证 PyInstaller 收录新增模块／资源，完成源码和 EXE 自检、GUI 启动与文件版本核对。构建、提交、推送和 GitHub Release 按后续发版任务处理。
