**历史阶段目标：** 当时在现有 GenerateTestQuestion 桌面工具中新增 OWASP 提示词工作区，用固定文本生成六字段记录并实际导出 JSON 与单表 Excel；该文本生成方式现已停用。

## 已确认的边界

- 最终 JSON 每项严格只有：`riskId`、`riskName`、`userA`、`userB`、`prompt`、`assertion`。
- `riskId` 与 `riskName` 独立校验，只要求为非空字符串；不得写死二者映射。
- 普通记录的 `userA == userB == ""`；跨会话记录中 `prompt == userB`，测试人员只发送 `userB` 或 `prompt` 一次。
- `prompt`、`assertion` 必须是去除首尾空白后非空的字符串；A/B 要么都为精确空字符串，要么都为去除首尾空白后非空的字符串。跨会话镜像使用原始字符串的精确相等，不做归一化。
- Excel 只有 `测试提示词` 一张表，列严格为：`风险编号 | 风险名称 | userA | userB | prompt | 断言`。
- OWASP 不读取网页素材、不调用爬虫、不自动发送任何 prompt；TC260 页面、历史批次与 13 列题库 Excel 不变。
- **已废止的阶段约束：** 当时仅允许固定文本生成。当前正式功能已由模型生成替换，故此约束不能用于验收。
- 生成输入中的风险 ID 去重后按 Top 10 目录顺序稳定轮转；未知 ID 立即拒绝；生成数量必须不少于去重后的已选风险数，因此每个已选风险至少有一条记录。`validate_prompt_record()` 仍允许未来任意非空编号和名称，以便读取新版本导出。

- [x] **Step 3: 实现实际批次与落盘**

`run_batch(params, output_root)` 只调用受控生成器与 Excel 导出器；`output_root` 为必传的已解析 `Path`，由 `owasp_pipeline.resolve_output_dir(settings)` 统一处理现有 `settings["outputDir"]` 语义。以独占隐藏暂存目录写入 JSON、Excel 与成功 manifest；三者完成后才通过同一卷上的目录重命名一次发布 `OWASP-YYYYMMDD-HHMMSS` 批次。这样不会出现 JSON 已发布、Excel 发布失败的半成品；同秒碰撞时追加稳定递增后缀，绝不覆盖其他批次。失败时最终批次目录仅可含失败 `manifest.json`，绝不能返回成功汇总。JSON 顶层必须是最终六字段数组，额外批次信息只可存在于单独的 `manifest.json`。
