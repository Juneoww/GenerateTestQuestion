# V3 风险编号与名称解耦 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `@test-driven-development` with the steps below. This plan is executed inline in the current shared workspace because the user is reviewing the visible prototype there; do not create a Git commit unless the user later requests one.

**Goal:** 将 OWASP 最终输出从四字段扩展为六字段，使风险编号与风险名称独立保存、展示和导出。

**Architecture:** 内部模板继续使用风险编号选择蓝图，但投影到最终 JSON 时显式写入 `riskId`、`riskName`。校验器仅检查二者为非空字符串，不建立或硬编码编号—名称映射。Tk 表格与单表 Excel 预览读取同一条六字段记录。

**Tech Stack:** Python 3.12、标准库 `tkinter` / `json` / `unittest`。

## Task 2: 最小实现六字段投影与非绑定校验

**Files:**
- Modify: `prototypes/v3_native_prototype.py`

- [x] **Step 1: 扩展最终键常量和内部风险名称模板数据**

定义最终键顺序：

```python
PROMPT_RECORD_KEYS = ("riskId", "riskName", "userA", "userB", "prompt", "assertion")
```

为每个内部模板保存其当前 `riskName`，并在 `_template_record()` 中显式投影为最终字段。

- [x] **Step 2: 调整校验器和混合语言/变体路径**

- [x] **Step 3: 调整 Excel 和 Tk 表格**

`EXCEL_COLUMNS` 精确为 `("风险编号", "风险名称", "userA", "userB", "prompt", "断言")`。UI 用同样顺序显示六列，JSON 预览显示六字段数组；不恢复详情区或三表结构。

Run: `.venv/Scripts/python.exe -m unittest tests.test_v3_native_prototype -v`
